WHAT IT DOES
================================================================================
"Edit template" sits next to "+ Add new" on the Report tab. It defines extra
sections that appear on every report UNDERNEATH Works completed. Each has a
heading, a type and an optional required flag:

    Free text   a paragraph
    List        one per line, rendered as bullets in the PDF
    Photos      its own photo area with its own heading

Reorder and remove in the same dialog. Removing a section does not touch any
report already written - see below.

Photos: the auto-collected set is unchanged and still pulls from submissions
since the last report. There is now an "Additional photos" area for anything
added by hand, uploaded through the same route the Site App uses, and the two
run together under one Photos heading in the PDF because a customer does not
care how a photo arrived.


THE DECISION THAT SHAPES EVERYTHING ELSE
================================================================================
A REPORT KEEPS THE TEMPLATE IT WAS WRITTEN WITH.

Saving a report stores `sections` on the report - a copy of the template at
that moment - and the view and the PDF render from that copy, never from the
live template.

Without it, editing the template rewrites history. Rename a heading and last
March's report, already issued to a customer and possibly argued over,
silently says something different from the PDF they are holding. Same
reasoning as an application freezing its variations when it is sent.

The cost is that a renamed heading does not reach old reports. That is the
right trade for a document that leaves the building.

Checked:
    existing report keeps its own:  "Delays (old wording)"
    new report uses the template:   "Site photos", "Delays"


MANUAL PHOTOS ARE A SEPARATE FIELD
================================================================================
`manualPhotos`, not appended to `photos`. Choosing a project re-pulls the
auto-collected set from submissions, and anything a person added by hand has
to survive that. One array would lose them on the next project change, which
is the kind of fault that only shows up after somebody has done the work
twice.


DEFAULTS ARE EMPTY, ON PURPOSE
================================================================================
No sections out of the box. A customer who never opens the editor sees
exactly the report they see today - no empty headings appearing on a document
they already rely on.


PERMISSIONS
================================================================================
Reading the template: anyone who can write a report, because it defines the
boxes they fill in. Writing it: management and admin only - a change affects
every report written from here on.


TWO THINGS CAUGHT WHILE BUILDING
================================================================================
`input` was declared INSIDE ReportModal and the two new components needed it.
That compiles and throws when the component renders - the same fault as four
other packages this fortnight. Hoisted to module scope and the whole file
re-scanned for others.

The PDF had the photo-embedding code inline in one loop. Rather than copy it
for the custom photo sections, it is now one `drawPhoto` function used by
both. Two copies would have drifted the first time one learned a new format.


SMOKE TEST
================================================================================
1. Report tab: "Edit template" next to "+ Add new". Add a free-text section
   and a photos section, save.
2. New report: both appear under Works completed, in order.
3. Fill them in, add a manual photo, save, reopen - everything still there.
4. Download the PDF: custom sections under Works completed, the list one as
   bullets, custom photos under their own heading, manual photos with the
   auto ones.
5. THE ONE THAT MATTERS: rename a section in the template, then reopen the
   report you already saved. It must still show the OLD heading. A new report
   shows the new one.
6. Change the project on a draft after adding a manual photo - the photo
   stays, the auto-collected set refreshes.
7. A report written before this package: unchanged, no new headings.
