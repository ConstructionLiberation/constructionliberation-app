PACKAGE 1119 - A build-up's own profit % takes priority over the quote's

Three files. Complete replacements. No re-seed. No env changes. Built on 1118.

  lib/buildups.js, lib/estimate.js
  pages/estimating/build-ups.js

Each build-up has a PROFIT % field beside its name, category and unit -
blank = the quote's. Set it (e.g. Attendances 15%) and, when the build-up is
added to an estimate, that becomes the item's profit % - which takes priority
over the quote's (e.g. 30%) in every rate and total. On the take-off the
item's Profit % column shows it (highlighted as differing from the quote) and
it can still be changed for that quote. "Try the rate" uses the build-up's
profit unless you type another. The build-ups file carries it (a "Profit %"
column on the Descriptions sheet; 0.15, 15 or "15%" all read as 15%).
Applies to items added after it is set - items already on estimates keep theirs.

Checked: on a quote at 30%, an Attendances build-up at 15% priced 1,000 ->
1,150 while another item priced 1,300; the quote moved to 35% -> Attendances
still 1,150, the other 1,350; "0.15" / "15" / "15%" -> 15%; the file round-
trips it. In a REAL browser (Chromium): Attendances Lump Sum, Profit % 15 ->
Try the rate profit 97.50 (15% of 650) and its default shows 15; saved 0.15.
