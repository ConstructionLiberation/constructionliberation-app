THE pkg863 LESSON, APPLIED BEFORE CONVERTING RATHER THAN AFTER
--------------------------------------------------------------
pkg862 flattened four near-identical fallback chains into one that matched none
of them, and pkg863 corrected it. That was luck - it was caught because you
questioned whether a test was needed.

So before touching anything this time I checked every chain at every call site.
Two would have been flattened again:

  design-email-test.js used NOTIFY_FROM_EMAIL with NO FORMS fallback. Mapping it
  to the existing 'notify' kind would have ADDED one. It gets its own kind,
  'notifyOnly'.

  THREE different base-URL chains exist - PORTAL_BASE_URL, PORTAL_URL and
  APP_URL - each with the same default. A single baseUrl() trying all three
  would change the answer for any site naming only one. baseUrl() now takes the
  caller's own env var name.

Four near-identical rules are not one rule. That is the whole lesson.


ALSO MOVED IN: three Microsoft mailbox settings
-----------------------------------------------
  MS_SYNC_GROUP        crm-sync@rockroofing.co.uk
  MS_BCC_MAILBOX       crm@rockroofing.co.uk
  MS_INTERNAL_DOMAIN   rockroofing.co.uk

Each customer has their own Microsoft tenant, so these are per-customer too.
MS_INTERNAL_DOMAIN matters more than it looks: it decides which emails count as
internal. Wrong for a customer, and their own staff get counted as clients.
