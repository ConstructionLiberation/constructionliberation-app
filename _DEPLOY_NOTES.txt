PACKAGE 1238 - Mark-up: move points; text the same size on screen and in the PDF

Two files. Complete replacements. No re-seed. No env changes. Built on 1237.

  components/DrawingMarkup.js          (the mark-up viewer - shared with the Design portal)
  lib/drawingPdf.js

MOVE POINTS: select a polyline or polygon and every point has a handle - drag it.
  - SNAP (when on) pulls the point onto the drawing's line ends and corners, or
    onto other marks' points - line and box ends snap too
  - hold SHIFT to line the point up with its neighbour - exactly level or plumb,
    whichever it is nearer - so edges can be made truly straight. Shift works
    while placing points too.
TEXT - why the PDF's text was bigger than on screen: text is sized in screen
pixels, so the PDF needs the width the drawing was shown at when the text was
placed. A note made before 1237 carried no width, and the PDF assumed 1,200
pixels - your full-screen window is about 1,800, so it printed half as big again
and wrapped onto more lines. NOW a text mark is drawn on screen at the same size
RELATIVE TO THE DRAWING on any screen (as a CAD annotation is), and the PDF
prints it at that size. Notes made before the width was recorded count as made
in the full-screen window (1,800 px).

Checked in a REAL browser (Chromium) on a PDF roof plan: a polygon placed roughly
- its 4 handles shown; a point dragged near the corner snapped exactly onto it
(0.8, 0.2); another Shift-dragged ended exactly plumb with its neighbour. A new
text note: its width recorded; the window shrunk 1,398 -> 898 px and the note went
18 -> 11.6 px - the same proportion of the drawing; an older note 23.3 -> 15.0 px
by the same rule (30 x width / 1,800). The PDF renderer re-run. All pages pass the
browser check. Built from your deployed packages (1022-1220) plus 1221-1237.
