PACKAGE 983 - the tab favicon, which 981 did not fix
================================================================================

Three files. ONE IS NEW.

  pages/api/favicon.js    <- NEW
  pages/_document.js      <- supersedes 981
  middleware.js           <- supersedes 981, repo root


WHAT I MISSED
================================================================================
981 made the WEB APP MANIFEST per tenant - the name and icon a phone uses
when someone adds the Site App to their home screen. It did not touch the
four hardcoded links in _document.js:

  /favicon.ico   /favicon-32x32.png   /favicon-16x16.png   /apple-touch-icon.png

Those are the BROWSER TAB icon, a completely separate mechanism, and they
are Rock's on every page of every tenant. Two icons, two mechanisms, and
fixing one looked like fixing both. It didn't, which is what you saw.


HOW IT WORKS
================================================================================
_document.js is server-rendered with no hook available, so the links point at
/api/favicon and that route redirects to the tenant's iconUrl, or to
/favicon.ico when it has none. A redirect rather than piping bytes, so the
file is still served as a static asset by the CDN.

302, not 301: a permanent redirect is cached by the browser effectively for
ever, and a tenant that set an icon later would never see it.

Rock has no iconUrl, so it redirects to /favicon.ico and nothing changes.

Same middleware problem as the manifest - an API route has no file extension,
so the passthrough rules that match .ico and .png cannot see it. Added to
both lists.


WHERE TO PASTE THE PATH - YOUR QUESTION
================================================================================
Upstash, the CONTROL database (control-registry), key tenant:demo. Add:

    "iconUrl": "/cl-logo.png"

Same place you put logoUrl and timezone. Not the demo tenant's own data
store - the control registry. It drives BOTH the tab favicon (this package)
and the home-screen install icon (981), so one field does both.

Allow two minutes for the registry cache, then a hard reload - browsers hold
onto a favicon harder than almost anything else. Incognito is the quick test.


A NOTE ON THE IMAGE ITSELF
================================================================================
cl-logo.png is 256px with transparent corners. As a 16px tab icon the
lettering around the badge will not be legible - it will read as a green
circle. That is normal for a detailed logo at favicon size and Rock's own
solution is a separate simplified mark (the square green ROCK tile). If the
demo wants the same, it needs a simplified square version, not the badge.
