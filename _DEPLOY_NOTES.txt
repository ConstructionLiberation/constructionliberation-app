WHAT IT DOES
------------
Every In Query invoice now carries a project, set by hand because Xero cannot
tell you - the cost being untagged is the whole reason it is on this tab.

  Bookkeeping > In Query   new sortable "Project" column with a picker on
                           each row. Amber while unset.
  The email                new Project column, showing "not set" in amber
                           where nobody has said yet.
  The review link page     a Project picker on each invoice card, editable
                           by the person who was asked.

Setting or changing it writes a line into the comment thread - "Project set
to J240 - Market Drayton." - so it reads as a history rather than a value
that silently appeared between one email and the next.

Nothing re-tags anything in Xero. This records the ANSWER; re-tagging in
Xero is still what moves the cost off the tab.


HOW IT IS BUILT
---------------
ONE project list, in lib/inquery.js, called by both APIs. Two lists that
drift is how a reviewer picks a project the bookkeeper cannot see.

Source is projects:registry - our own record of every project Xero has ever
returned. One Redis read, survives a deleted tracking option, and the review
page still never touches Xero, which matters because the person holding that
link may be outside the business.

Excluded from the list: anything in config:hidden-projects, plus the four
tracking options that are not projects (In Query, Old Projects, Internal,
Head Office Cost). Offering "In Query" as the answer to "which job is this
In Query cost for" is the obvious own goal.

The email reads the project off the stored record, not off what the browser
posted, so what goes out is what is saved.


AFTER DEPLOYING - CHECK
-----------------------
1. Bookkeeping > In Query. The Project column shows, amber and "Not set".
2. Pick a project on one row. It saves immediately - no save button - and a
   line appears in that invoice's comments.
3. Sort by Project. Rows group by job number.
4. Send the list to yourself. The email has a Project column.
5. Open the link from the email, change the project there, then go back to
   the Bookkeeping table and confirm it followed.
6. Approve something on the link page and confirm the project SURVIVES -
   approving must not wipe it.


ONE THING TO BE AWARE OF
------------------------
The review page now shows the project list to whoever holds the link. For
Contracts Managers and site staff that is nothing; if you ever send an In
Query item to somebody outside the business, they can see your job numbers
and names. Say the word and it becomes a free-text box for external
reviewers instead.
