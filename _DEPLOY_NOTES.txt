pkg908 - Applications list stale after create and delete
========================================================

REPLACE (1 file, existing - no new files to create):

  pages/api/applications.js

WHAT WAS WRONG
--------------
commit() re-reads the project, applies the change, saves, and returns the
record it wrote. Three actions threw that return value away and responded
with `project.applications` - the copy read at the TOP of the handler,
before the write.

So the server saved correctly and then reported the pre-write state:

  create          responded without the new application  -> nothing appeared
  delete          responded still holding the deleted row -> nothing vanished
  set-hidden-pos  same shape (you may not have noticed this one)

The data in Redis was always right. Only the response was stale, which is
why a refresh has been fixing it.

WHAT CHANGED
------------
All three now capture commit()'s return and respond from it.
No other file touched. No new imports. Import graph unchanged.

AFTER DEPLOYING - CHECK
-----------------------
1. Applications page, pick a project with locked contracted rates.
2. Create an application. It should appear in the list with NO refresh.
3. Delete a draft. It should vanish with NO refresh.
4. Hide a PO in the materials picker - takes effect immediately.

NOT FIXED, DELIBERATELY
-----------------------
'save' and 'submit' write the whole `apps` array back from the stale read.
Same family, wider blast radius, and they return the updated row so the UI
is correct today. Worth a narrow rewrite, but not blind and not at the same
time as this.
