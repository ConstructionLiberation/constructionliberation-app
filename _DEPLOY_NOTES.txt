WHY THE DEMO WAS EMPTY
======================
The seed wrote 49 keys to demo's database successfully. The portal showed
nothing.

pages/api/dashboard.js DOES read dashboard:cache first - I had it wrong when I
said it only wrote it. But the cache-first path is guarded by a field-presence
check on the first row: nineteen marker fields that must be exactly true, and
nine more that must merely exist. Each was added when a record shape changed,
to stop an old snapshot serving stale values after a deploy. A sensible guard.

My rows carried none of the _v1 markers. So the guard rejected the cache, the
code fell through to the live Xero call, and that 401'd on a tenant with no
Xero connection. 49 keys written, nothing on screen.

This is the same guard noted in CODE-NUANCES: "dashboard:cache requires a
field-presence guard that must be bumped whenever record shape changes". It
bit in the other direction - not a stale cache being served, but a fresh one
being refused.


WHAT CHANGED
============
projectCacheRow() now emits all 28 fields the guard checks. The list was
EXTRACTED FROM THE CONDITION PROGRAMMATICALLY rather than transcribed by eye -
there are 28 of them on one 1,400-character line and reading it correctly by
hand is not a reasonable thing to ask of anyone.

Rows now carry 93 fields, up from 76.

A note is written into the file: IF A NEW MARKER IS ADDED TO THAT CONDITION,
IT MUST BE ADDED HERE TOO, or the demo silently empties. That is a real
coupling and there is no way to avoid it while the seeder writes the cache
directly - which is the compromise already documented in pkg941.


BEFORE YOU RE-SEED
==================
The demo tenant already has the old rows, and 'seed' refuses a populated
tenant. Wipe first:

  await fetch('/api/admin/seed-demo', {
    method:'POST', headers:{'Content-Type':'application/json'},
    body: JSON.stringify({ action:'wipe', id:'demo', confirm:'demo' })
  }).then(r=>r.json()).then(console.log)

Then seed again with the same call as before. Use the same `seed` value if you
want the identical dataset back; omit it and you get the default 20260920.
