A DOOR LOCKED FROM THE INSIDE
-----------------------------
You asked whether you could move the platform to its own domain first. You
could not, and the reason is a fault in what I built.

withTenant demanded a platform SESSION before letting anything through on a
platform host. But the login route is itself wrapped. So:

    no session -> cannot reach login -> cannot get a session

Point a domain at the project today and you would have been locked out of it
with no way in except editing an environment variable back out again.

Fixed: no session is required to REACH the platform host. Authorisation is done
where it belongs - requireRole plus the PLATFORM_ADMINS check inside the
platform route.


A SECOND PROBLEM, WORSE
-----------------------
Pointing a domain at this Vercel project makes it serve the WHOLE app. So
admin.constructionliberation.com would also have answered /crm, /wip, /retention
and every other route - and, having no customer database of its own, would have
fallen back to reading ROCK'S.

One address quietly serving another company's portal is the exact thing this
entire exercise exists to prevent, and I would have handed it to you as a
feature.

Now, on a platform host, only two things are reachable:

    /api/portal-auth     signing in
    /api/platform/*      the platform itself

Everything else is 404. Not 403 - a 403 confirms the route exists.

And middleware redirects any other PAGE on that host to /platform, so the screen
matches the API rather than drawing a portal that then fails every call.


WHAT THIS MEANS FOR YOUR LOGIN - read this before setting PLATFORM_HOSTS
------------------------------------------------------------------------
The platform host has no user store of its own, so signing in there
authenticates against ROCK'S user records - the same username and password you
use today.

That is interim and it is not where this should end up. A platform login should
live in the control database, independent of any customer, so that Construction
Liberation is not administered through Rock Roofing's user list. That is its own
package and it matters more once the account ownership question you raised is
settled.

Worth knowing now so you are not surprised: moving the platform to its own
domain does NOT yet move the login off Rock.

TO SET THE DOMAIN UP, when you want it
--------------------------------------
  1. Add the domain to the Vercel project - admin.constructionliberation.com or
     whatever you choose.
  2. Add the environment variable:

         PLATFORM_HOSTS = admin.constructionliberation.com

  3. Redeploy.
  4. Visit it. You should land on /platform, and be asked to sign in with your
     Rock credentials.
  5. Check that app.rockroofing.co.uk/platform ALSO still works - it will, until
     TENANCY_ENABLED is set. After that, only the platform domain will.

None of this is required before registering Rock. It can wait until after, and
registering Rock is the more useful thing to get done.
