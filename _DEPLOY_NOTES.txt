One file. Complete replacement. No re-seed. No env changes. Built on 1217.

  lib/projectPeople.js

WHY THE ADDRESS WAS BLANK: a project keeps its address in one of two fields -
projectAddress (the IHM / Project Details) or siteLocation (older and
hand-added projects). The Site App's own project list reads either, but the
address rule purchase orders use (the portal's too) read only projectAddress,
so a project with its address in siteLocation came back blank - in BOTH the
Site App and the portal.
NOW: projectAddress, else siteLocation - unless the address was deliberately
set or cleared in Project Details, which still wins. The same rule feeds the
project report and the project-complete checks, so they pick these addresses
up too.
If a project's address is still blank after this, it has no address in
Project Details / the IHM - add it there.

Checked through the real routes: a project with projectAddress, one with only
siteLocation, and one with a Project Details override - all three now give
their address, in the Site App and the portal (siteLocation was blank in both
before). The rule: no override -> siteLocation used; override cleared on
purpose -> stays blank; override set -> wins. All server routes compile.
