PACKAGE 1009 - procurement: the save that wasn't, and the pound signs
================================================================================

Three files. Complete replacements. No re-seed.

  pages/operations/project-management/procurement.js
  pages/operations/project-management/procurement-savings.js
  components/ProcurementSavings.js


THE SAVE
================================================================================
    await fetch('/api/procurement', { method: 'POST', ... })
    setEdit(null); load()

The response was never looked at. The API answers

    400 { error: 'Activity/Package or Supplier required' }

for a new row with neither of those filled - so the dialog closed, the list
reloaded without the row, and nothing said why. That is indistinguishable
from "it doesn't save".

It now reads the response and shows the API's own message above the table.
Any other failure names its status and says nothing has been changed.

THIRD SWALLOWED RESPONSE TONIGHT. The variations tracker cost four packages
because a 409 never reached the screen; the retention tracker rendered a 403
as an empty dataset and had your bookkeeper's figures quietly disagreeing
with yours. All three are the same habit: a fetch whose result is assumed.

That is now worth a sweep of its own - every fetch that does `|| []` or
`catch {}` on a response it never checked. Not tonight, but it belongs near
the top of the list, because these have cost more time than the faults
underneath them.


THE POUND SIGNS
================================================================================
Three module-scope formatters, one per file, all hardcoded to en-GB/GBP:

    procurement.js           fmtMoney   used by Procurement and ProcModal
    ProcurementSavings.js    gbp        used by MoneyInput
    procurement-savings.js   gbp        used 6 times

Each now lives inside the component that uses it and takes money() from
useFormat(), keeping its own shape - the em dash for a blank on the savings
pages, the leading minus on procurement. Same pattern as pkg957 onwards.
These are three of the thirty inline formatters that survived the currency
sweep because they carry no literal pound character in a form my greps saw.
