PACKAGE 978 - the CRM deal that flashes and opens on the second click
================================================================================

One file. Complete replacement.

  pages/crm.js          <- SUPERSEDES 963 AND 964's changes to this file


WHAT WAS HAPPENING
================================================================================
Opening a deal does two things:

    const openDealById = (id) => { setOpenId(id); router.push({ query: { deal: id } }) }

and an effect reads it back off the URL:

    setOpenId(Number(q))

Pipedrive ids are numeric, so on Rock that round-trips cleanly and always
has. The demo generator produces ids like 'd1000'.

Number('d1000') is NaN. So:

  click      -> setOpenId('d1000'), the deal view renders        <- the flash
  URL push   -> effect fires -> setOpenId(NaN) -> deals.find()
                matches nothing -> the view closes
  click again-> setOpenId('d1000') again, but the query is ALREADY deal=d1000,
                so the effect does NOT re-run, and it stays open

Which is exactly "it flashes, then opens on the second click". Nothing to do
with the seeded data being wrong - the data is fine, the app assumed every
deal id is a number.


FOUR MORE OF THE SAME, WHICH WOULD HAVE BEEN WORSE
================================================================================
The activity handlers do Number(dealId) in four places:
completeActivity, addActivity and patch twice. Those do not flash - they
silently do nothing, because NaN matches no deal. On demo, completing or
editing an activity from the CRM would simply not have worked, with no error.

And three lines above one of them, the same file already compares with
String(a.dealId) === String(dealId). One rule, two spellings, sitting next to
each other.


THE FIX
================================================================================
One module-scope helper, used at all five sites:

    const dealKey = (v) => { const raw = String(v); return /^\d+$/.test(raw) ? Number(raw) : raw }

Coerce only when the id really is all digits. Evaluated the line straight out
of the file rather than trusting it by eye, because if that test failed for
digits then ROCK's numeric ids would stop matching and the CRM would break
for the live tenant:

    '1234' -> 1234 (number)    1234 -> 1234 (number)    '0' -> 0 (number)
    'd1000' -> 'd1000'         'abc' -> 'abc'           '' -> ''


SMOKE TEST
================================================================================
1. Demo CRM: click a deal from the board. It should open first time.
2. Demo CRM: click a deal from the list view. Same.
3. Demo: open a deal and complete an activity, then edit one. Both were
   silently doing nothing.
4. Reload the page on a deal URL - that is the effect path on its own.
5. ROCK CRM: open a deal, complete an activity. This is the regression that
   matters; Rock's ids are numeric and must still behave identically.
