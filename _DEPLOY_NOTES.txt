PACKAGE 959 - "No chase emails sent yet" on every invoice
================================================================================

Two files. Complete replacements. No overlap with 958 - deploy both together.

  lib/chaseEmailTemplates.js
  lib/outstandingInvoicesReport.js


WHAT IT WAS
================================================================================
Every invoice in the weekly PDF says

    Emails sent
    No chase emails sent yet.

including ones whose Comments list four sent chases. INV-1743 has four. It has
been wrong since the chase system was built.

The row builder in lib/outstandingInvoicesReport.js reads

    emails: m.emails || [],

and m.emails DOES NOT EXIST. Chases are stored under m.chases, keyed by
stage, written by the record-chase action in pages/api/outstanding-invoices.js.
So the field was always an empty array and the PDF always printed the empty
state.

This is the second fault class from the lessons, server to server instead of
client to server: a reader taking a field off a structure that never carries
it. Nothing in the build, the compile or the bundlecheck looks at that. The
PDF's own line even says "placeholder until chase emails are built" - the
chase system was built and this was never wired back up.

The email that carries the PDF makes it worse by promising the opposite:
"The full list, with comments and emails to date for each invoice, is attached
as a PDF."

NOT CAUSED BY 957 OR 958. Predates both.


WHAT IT IS NOW
================================================================================
chaseList() reshapes m.chases into what the PDF renders - { at, type, to } -
sorted oldest first. `to` is stored as an array in some records and a bare
string in others, so both are handled and joined with a comma.

The stage LABEL comes from a new CHASE_STAGE_LABELS export, DERIVED from the
CHASE_TEMPLATES array rather than typed out again. There were already three
hand-written copies of that map and two had drifted - chaseEmailTemplates.js
calls the last stage "Withdrawal from Contractual Obligations", the API calls
it "Withdrawal notice".


CHECKED
================================================================================
- Ran chaseList against realistic records: three stages out of order, one with
  `to` as a string, one with `to` as a two-address array, one with no subject.
  Comes back chronological with the right labels. Undefined and {} both give
  [], which is the empty state the PDF already handles.
- Both files compile clean.


DELIBERATELY NOT FIXED HERE
================================================================================
pages/api/outstanding-invoices.js line 107 still has its own inline stage
label map, and it is the one that has drifted. Pointing it at
CHASE_STAGE_LABELS is a one-line change, but it would alter the text written
into future comment records, which is stored data rather than a rendering.
Worth doing on purpose, not as a side effect of this.

================================================================================

Overdue 2, Overdue 3 - with dates and recipients. INV-1729 (Hollis Croft) has
