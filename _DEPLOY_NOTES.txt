pkg883 - The bookkeeper can use the In Query table
==================================================

ONE FILE.  pages/api/bookkeeping-inquery.js  - not new.

Nothing to do with tenancy. A role list that was wrong, and has been.


WHAT WAS WRONG
--------------
Every endpoint the Bookkeeping page calls allows the accounts role. Except one:

    bookkeeping.js            accounts, management, admin
    import-bills-bulk.js      accounts, management, admin
    bookkeeping-inquery.js    post-contract, management, admin   <- the odd one

So your bookkeeper could OPEN the In Query table and not USE it. Assigning
someone returned "You do not have access to this."

It gets odder. lib/roles.js says:

    'bookkeeping': ['accounts', 'management', 'admin']

post-contract cannot reach the bookkeeping AREA at all. So this endpoint was
allowing a role that can never open the page, and refusing the only role that
can. The list looks copied from a commercial endpoint rather than chosen.

The In Query table appears on exactly one page - pages/bookkeeping.js - so there
is no other route by which a post-contract user would reach it.


THE FIX
-------
    accounts, post-contract, management, admin

accounts added, which is the point. post-contract KEPT rather than removed: it
is almost certainly dead, since that role cannot reach the area, but removing a
permission on a hunch is how you break something at 8am on a Monday. It costs
nothing to leave.


CHECKS I RAN
------------

- listed every endpoint pages/bookkeeping.js and components/InQueryTable.js
  call, with their role lists - this was the only one out of step
- checked AREA_ACCESS to confirm accounts genuinely belongs there
- confirmed InQueryTable is used on one page only
