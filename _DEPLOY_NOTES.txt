1. TWO JOBS REPORTING GREEN WHILE DOING NOTHING
-----------------------------------------------
    crm-call-volume        1 ms    ok: true
    crm-daily-activities   1 ms    ok: true

One millisecond. refreshCallVolume returns

    { ok: false, error: 'Not configured. Missing in Vercel: ...' }

the moment it finds no 8x8 credentials - but sends it as a 200. The heartbeat
read the status code and recorded a success.

So the monitoring said healthy for two jobs that were exiting immediately. That
is the precise failure the monitoring exists to catch, and it was being produced
BY the monitoring.

Fixed: a 200 carrying { ok: false } is now a failure. A handler that says it
failed has failed, whatever code it chose to send.

EXPECT THOSE TWO TO TURN RED after this deploys. That is correct. 8x8 is on your
backlog, so "not configured" is the true state - it just was not being reported.


2. THREE JOBS WITH NO MONITORING AT ALL
---------------------------------------
forms-weekly-notify, deliveries-notify and rams-reminders are called as
FUNCTIONS from hs-expiry-email, not as routes. forEachTenant never saw them, so
they recorded nothing and did not appear.

hs-expiry-email ran for 8.5 seconds and reported success. Had the RAMS reminders
inside it thrown and been swallowed, it would have looked identical.

Each now records its own heartbeat and appears beside the rest, judged against
the dispatcher's daily schedule and labelled "runs inside hs-expiry-email".


3. MY OWN DESIGN FLAW
---------------------
I told you deep-sync, wip-sync and pipedrive-sync would show as "not scheduled".
They did not appear at all.

A cron only appeared if it was in vercel.json or had written a heartbeat. Those
three have NEITHER, so the one status I built specifically for them was
unreachable - and a cron nobody scheduled is exactly the one most likely to be
forgotten.

cron-health now also lists the pages/api/cron folder, so a cron file with no
schedule and no history is visible rather than absent. Read from the folder, not
from a list kept in the file, because a list kept there is a second copy of the
truth.

CAVEAT, and I need you to check this: reading the folder from inside a
serverless function may not work on Vercel. The response now carries

    folderListed: true | false

If it comes back FALSE, the three parked crons are still invisible and I will
find another way. Tell me either way.
