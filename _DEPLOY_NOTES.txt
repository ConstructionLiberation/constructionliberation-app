pkg896 - The manifest error on every page load
==============================================

ONE FILE.  middleware.js  (repository root)


WHAT IT WAS
-----------
    Manifest: Line: 1, column: 1, Syntax error.    /site.webmanifest:1

The file is fine. It exists in /public and it is valid JSON - I parsed it.

MIDDLEWARE WAS INTERCEPTING IT. The open list allowed /favicon and
/rock-logo.jpg, one filename at a time, and missed everything else. So the
browser's request for site.webmanifest had no session, was redirected to /login,
and the browser got an HTML page where it expected JSON.

/apple-touch-icon.png had exactly the same problem.


WHY IT IS WORTH FIXING RATHER THAN IGNORING
-------------------------------------------
Day to day it is a console warning nobody reads.

But site.webmanifest is the file that decides WHAT THE SITE APP IS CALLED and
WHICH ICON IT GETS when an operative adds it to their phone's home screen. That
has been silently failing for every operative who has ever tried - they would
have got a generic browser icon and the page title, with nothing to explain why.

apple-touch-icon.png is the iPhone equivalent, and was equally blocked.


THE FIX
-------
Static files are allowed by EXTENSION rather than one filename at a time:

    /\.(webmanifest|ico|png|jpg|jpeg|svg|gif|webp|woff2?|ttf|txt|xml)$/i

Added to BOTH lists - the main one and the Site App passthrough. The Site App one
matters more, since siteapp.rockroofing.co.uk is where an operative actually
installs from, and it was missing it too.

By extension so the next icon or font added to /public does not need remembering.
None of these file types can carry data.

Checked it does not open anything it should not:

    /site.webmanifest       open      /wip                     closed
    /apple-touch-icon.png   open      /api/dashboard           closed
    /favicon.ico            open      /retention               closed
    /robots.txt             open      /api/project/abc/report  closed


CHECKS I RAN
------------
- esbuild compile: 0 errors
- middleware still imports only next/server - it runs at the edge
- confirmed the rule is in both lists
- ran the pattern against six paths that must open and six that must stay closed
- parsed site.webmanifest to confirm the file itself was never the problem

My first attempt at this edit asserted and wrote nothing, because the anchor
line appears TWICE in the file. That is the assert doing its job - it stopped me
patching one list and leaving the other, which is the half-fix that would have
left the Site App still broken.


ONE FOR LATER, NOT NOW
----------------------
The manifest hardcodes "Rock Roofing" as the app name and points at Rock's
icons. Under multi-tenancy every customer's Site App would install as "Rock
Roofing" on their operatives' phones.

It needs to be served per customer rather than as a static file - a small API
route reading the customer's name and logo. Not urgent, but it belongs on the
list with the other per-customer branding.


WHAT TO CHECK
-------------
1. Reload any page. The Manifest syntax error should be gone from the console.
2. On your phone, on siteapp.rockroofing.co.uk, add it to the home screen. It
   should now be called "Rock Roofing" with the proper icon.
