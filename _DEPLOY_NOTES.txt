pkg873 - The three parked crons, made visible
=============================================

ONE FILE.  pages/api/admin/cron-health.js  - replaces the pkg872 version.
Read only. No behaviour change.


WHAT HAPPENED
-------------
pkg872 tried to list the pages/api/cron folder at runtime so a cron with no
schedule and no history would still appear. Your reading came back

    folderListed: false

so it does not work inside a Vercel function. The three parked crons were still
invisible, which was the whole point of that change.


WHAT IT DOES NOW
----------------
An explicit list:

    const UNSCHEDULED_CRON_FILES = ['deep-sync', 'wip-sync', 'pipedrive-sync']

THIS IS A SECOND COPY OF THE TRUTH, AND I HAVE WRITTEN THAT IN THE FILE RATHER
THAN QUIETLY ADDING IT. The fault class that has cost this project most is one
rule kept in two places and left to diverge, so a list like this needs a reason:

  - it covers ONE case: a cron file that has never run AND has no schedule
  - a cron WITH a schedule comes from vercel.json automatically
  - a cron that has EVER RUN registers itself by writing a heartbeat
  - so the only way it drifts is a new cron file that is never scheduled and
    never runs - which would be invisible anyway

The failure mode of the copy is no worse than not having it. That is the test I
applied, and it is the only reason I am comfortable with it.

The response now also returns unscheduledFromList, so the report says plainly
which names are hand-written rather than discovered.


THE BETTER ANSWER I DID NOT TAKE
--------------------------------
webpack's require.context enumerates the folder at BUILD time with no list at
all. It is genuinely better.

I did not use it because it fails the BUILD if it cannot resolve, and I broke
your build once already today with an import that compiled fine on its own. A
build failure costs more than this list does.

If you would rather have no list, say so and I will switch - but I would want to
do it on its own, not bundled with anything else, so that if the build goes red
there is exactly one thing to undo.
