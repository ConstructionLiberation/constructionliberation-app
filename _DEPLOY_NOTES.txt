===========================================================================================

REPLACE (2 files, both existing - no new files to create):

  pages/project-cashflow.js
  pages/api/project-cashflow.js

NOTE: same filename in two folders. Both must be replaced.


CHANGE 1 - the live list is now the Project Financials register
---------------------------------------------------------------
Was: Operations projects with status active or draft.
Now: every Xero project the dashboard returns, minus the SHARED hide list
     (config:hidden-projects - the same one Project Financials uses).

So a project set up in Xero and commercial but never created in Ops now has
a row; an old job left active in Ops no longer sits here forever. Hide a
dead job on Project Financials and it goes from both.

NO KEY CHANGE AND NO MIGRATION. Forecast keys were already "L:<jobNo>" and
the page already joined job numbers to Xero ids to resolve names - that join
has been load-bearing all along, which is why the names on this page have
always been right.

The planner is still read, but only to SHADE rows - who is on site, planned
start. A project the planner has never heard of gets no shading and is
otherwise normal.


CHANGE 2 - negotiated projects are added by hand
-------------------------------------------------
Was: every CRM deal at the Negotiating stage, automatically. A deal changing
     stage silently changed the cash flow.
Now: "+ Add project" next to the Negotiated heading. Name, optional customer.
     An x on each hand-added row removes it.

Removing REFUSES while forecasts exist against it, rather than leaving
cashflow:hyp-apps:<key> in Redis with nothing on screen pointing at it -
invisible here, still counted by Business Financials.

ONE-TIME SEED SO NOTHING IS LOST. The first time the new code runs it scans
for negotiated forecasts that already exist, names them from the CRM, and
writes them into the new store. After that the CRM is never read here again.
It only runs when the store has never existed - an empty list is a
deliberate "I removed them all" and is not re-filled.
