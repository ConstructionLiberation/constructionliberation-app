THE SAME MISTAKE AS THE LOST REASONS
================================================================================
Both metrics filter on the lead source BY NAME:

    scoredFiveFor('glenigan')         -> getLeadSource(d).includes('glenigan')
    scoredFiveFor('actively chased')

The seeder was writing:

    Referral | Tender list | Repeat client | Website | Cold approach

Plausible words. NONE of them an option in lib/crmFieldSchema.js, which
offers Glenigan / Website New Build / Website Refurb / Actively Chased /
Other. So the dropdown on a deal showed one set and the data held another,
and neither metric could ever match.

Now weighted so both carry volume: four parts Glenigan, three Actively
Chased, three Website, one Other. Checked against the schema - every value is
a real option.


AND A SECOND CONDITION NOBODY COULD HAVE SEEN
================================================================================
Those metrics also need a score of five or more:

    const score = parseInt(d.label)      // d.label <- f.project_score

project_score was never seeded, so every score was NaN and both metrics would
have read 0 even with the lead source fixed. Two conditions, one metric, and
fixing either alone changes nothing on screen - which is exactly how the last
three packages went.

Seeded 3 to 10, skewed away from the bottom: a project nobody rates above 4
is not one anybody chases.


STILL BLANK, AND CORRECTLY SO
================================================================================
"Emails sent externally" reads /api/email-volume, which is fed by the
Microsoft Graph sync. Demo has msSyncGroup empty, so there is nothing to
report and the card shows a dash rather than a zero - the distinction the
scorecard draws between "no data" and "none".

Seeding a number there would invent a figure rather than demonstrate a
feature, which is the opposite of what the rest of the demo does. Leave it,
and say what it is if asked: it comes from the mailbox sync, which is not
connected on the demo tenant.
