ON THE TAKE-OFF

REVISIONS
  Issue Rev A (needs the estimate saved and the profit % set; asks for an
  optional note):
    - freezes the quote as Rev A - kept for good, a true copy no later edit
      can reach
    - the estimate carries on as Rev B
    - the linked CRM deal's value is set to the issued total, with a value
      history entry exactly like an edit in the CRM ("Value: 0.00 -> 20,943.09
      (estimate Q-1042 Rev A, by ...)") - so Value of work priced counts it
  "Changes since Rev A" updates live as you work: items added / removed,
  quantity, rate, profit override, rate-only, the quote's profit / MCD /
  labour factor, and the total's movement. Each issued revision lists what
  changed from the one before.
  A save cannot rewrite issued revisions; issuing is refused if someone has
  changed the estimate since you opened it.

+ PRELIMS - a Prelims section and item (per item, qty 1) with lump sums for
  Lodge (Prelims), Management (Management) and Attendances (Attendances); it
  opens in the pop-out to fill in. Each line keeps its cost category.

COST BREAKDOWN - every cost by category (Materials, Labour, Delivery,
  Management, Prelims, Attendances...) before profit and MCD.
BUDGETS BY SUPPLIER - the product lines by each product's supplier. These are
  the figures to carry to the Internal Handover / procurement schedule when the
  job is won (that link comes with the handover work).

ONE THING TO KNOW: if someone has a deal open in an older CRM tab while a
revision is issued, and then saves that deal, their older copy replaces the
new value - the CRM's existing behaviour between any two users, not new here.
The issued revision itself is unaffected; re-issuing restores the value.
