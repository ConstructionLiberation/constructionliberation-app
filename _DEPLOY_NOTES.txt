PACKAGE 982 - Rock's retention page is broken. Deploy this first.
================================================================================

ONE file. Complete replacement. AHEAD OF 979, 980 AND 981.

  pages/retention.js      <- includes 960, 961, 970 and 971

This is a LIVE page on Rock throwing on load, and it has been since 960
deployed this morning.


WHAT BROKE
================================================================================
960 moved `fmt` off module scope into RetentionPage, because money() comes
from a hook. pages/retention.js has a SECOND component - InlineNumberCell -
which renders a formatted value in two places and was left reaching for a
const that no longer exists:

    ReferenceError: fmt is not defined

Same fault as Shell (965), UpcomingTable (975) and NAV (979): a value
declared in one component and used in another.


WHY MY CHECK MISSED IT, WHICH IS THE PART THAT MATTERS
================================================================================
IT DIDN'T. The ownership scan flagged it when I built 960 - it printed
"2 fmt calls in InlineNumberCell". I then ran a second check to confirm:

    awk 'NR>46 && NR<330 && /\bfmt[A-Z]?\(/' pages/retention.js

It printed nothing, so I recorded InlineNumberCell as a false positive and
moved on.

awk does not support \b as a word boundary. In POSIX ERE, \b is a BACKSPACE
character. The pattern could never match anything. My verification tool was
broken, and I trusted it over the scan that was right.

The lesson this codebase already had written down - a diagnostic must be
able to state what it did not look at - and I built one that silently
matched nothing and read that as proof.


WHAT I DID AFTER FIXING IT
================================================================================
Re-ran the scan across EVERY file touched today that uses useFormat, in
Python, with three corrections to the scan itself:

  - module-scope declarations count as in scope for components below them
    (the previous version flagged 27 files that were fine)
  - imported names count as declared
  - only CALLS count as uses, not the bare word appearing in a string

Result: clean, with InlineNumberCell the only real fault. That scan is now
worth something; the awk one never was.
