pkg918 - Site App Users: a search box on the project picker
============================================================

REPLACE (1 file, existing - no new files to create):

  pages/operations/users.js

Note the folder: pages/operations/, not pages/.


WHAT IT DOES
------------
The project access dropdown on Site App Users now opens with a search box
at the top. Type a job number or a project name and the tick list narrows.
Everything else about it is unchanged - "All projects" still sits above the
list, ticking still works the same way.

Matches job number OR name, so "J178" and "Gas Lane" both find it.
Sticky, so it stays reachable once the list scrolls.
Autofocused, so you can open and type without reaching for the mouse.
Escape clears the search; clicking away closes and clears it.

ONE THING THAT NEEDED THINKING ABOUT. Searching narrows the list; it does
not untick anything. But a ticked project scrolling out of view reads as
having been cleared, and the natural response is to tick it again somewhere
else. So when a search hides projects that are already selected, it says so:

  "3 selected projects are hidden by this search. They are still selected."


AFTER DEPLOYING - CHECK
-----------------------
1. Add or edit a Site App user, open Project access. Search box at the top,
   already focused.
2. Type part of a job number - list narrows. Tick one.
3. Search for something else - the amber line should say one selected
   project is hidden.
4. Clear the search and confirm it is still ticked.
5. Save, reopen the user, and confirm the right projects are on.


NOTE FOR WHOEVER EDITS THIS FILE NEXT
--------------------------------------
The dropdown boilerplate in ProjectAccessPicker is duplicated by another
picker in the same file - identical outside-click useEffect, same variable
names. A whole-file find and replace on any of it will hit the wrong one.
These edits were scoped to the component deliberately.
