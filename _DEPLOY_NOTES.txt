2. THE REPLY-TO FIELD WAS MISLABELLED
-------------------------------------
You said reply-to is often the logged-in user. You are right, and the code
already does that - I checked all 14 places that set it:

    reply_to: b.sentBy     variations and applications - the person who sent it
    reply_to: REPLY_TO     password resets, login details, pre-start
                           notifications, operative invitations, problem reports

So the customer-level setting is a FALLBACK for emails with no sending user, not
an override. The form said "Reply-to (their own address)", which reads like it
applies to everything.

Relabelled "Reply-to for system emails", with a note listing which ones and
saying plainly that variations and applications are unaffected.
