PACKAGE 998 - "Project not found" when clicking a project
================================================================================

One file. Complete replacement. Mind the folder and the brackets.

  pages/api/project/[id].js

No re-seed.


THE CAUSE - THE SAME ONE, A THIRD TIME
================================================================================
Line 12 of that route:

    let tokens = await getTokens()
    if (!tokens) return res.status(401).json({ error: 'Not connected to Xero' })

That ran BEFORE the dashboard cache lookup and before the project register
fallback. So on a tenant without Xero every project page answered "Project
not found" no matter how complete its data was - and clicking a project name
from Project Financials is exactly that request.

The file already argues the opposite case forty lines further down, for a
project whose Xero tracking option has been deleted:

    "we still hold its applications, contracted rates, variations and
     retention, so the page must still open"

Same reasoning applies when the ACCOUNTING is absent rather than the tracking
option. The guard was written when Xero was always there.


THE FIX
================================================================================
No tokens is no longer a refusal. The route resolves the project from the
dashboard cache, then from projects:registry, exactly as it already did. The
Xero category lookup - the only step that genuinely needs a connection - is
now skipped rather than attempted, and "no tenant id" is a 500 only when
there ARE tokens, because a connection without one is broken while no
connection at all is simply a customer who does not use Xero.


THE PATTERN, NOW WORTH WRITING DOWN
================================================================================
Three faults this evening, all the same:

  996  28 routes deleted a cache nothing could rebuild
  997  dashboard.js refused the cache when asked to sync without tokens
  998  the project route refused before ever reading the cache

On a single-tenant app with Xero permanently connected, "no tokens" only ever
meant BROKEN. With a second tenant it means NOT APPLICABLE, and those want
opposite behaviour. Every remaining `if (!tokens) return 401` is a candidate.
I checked: three others remain, in business-financials.js, dashboard.js (the
genuine sync path, correct) and sync-chart-of-accounts.js. The first is worth
looking at when Business Financials gets its data.


ONE THING THAT IS NOT A BUG
================================================================================
Your retention release ticks, and anything else you set by hand, went because
you WIPED. retention:entries is in DEMO_KEY_PREFIXES, so a re-seed
regenerates every record and discards what you had marked.

Nothing in the app is losing your work. But it does mean: once the sweep is
finished, stop re-seeding. Anything you set up for the demo only survives
until the next wipe.
