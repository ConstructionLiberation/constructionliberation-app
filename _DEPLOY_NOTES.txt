WHAT IT IS
----------
You asked for a way to see whether the crons are working. The heartbeats have
been recording since pkg858, so there is real data to read now.

    /api/admin/cron-health

For every cron: its schedule, when it last ran, how long it took, whether it
succeeded, and whether it is OVERDUE.


THE POINT IS THE ABSENCES
-------------------------
A cron that ERRORS shows up in the Vercel log. A cron that silently STOPS
RUNNING writes nothing, logs nothing, and looks exactly like a quiet week.

That is how three of yours came to have no schedule at all without anyone
noticing - deep-sync, wip-sync and pipedrive-sync - and it is how, under
multi-tenancy, a sync could stop for one customer while working for everyone
else.

Statuses:
  ok               ran within its expected interval
  OVERDUE          scheduled, but has not run when it should have
  last run failed  ran and threw
  never run        scheduled, no heartbeat yet
  not scheduled    the file exists, nothing calls it  <- your three


SCHEDULES ARE READ FROM vercel.json ITSELF
------------------------------------------
Not copied into a list in this file. A second copy of the schedule drifts from
the real one, and a monitoring page reporting against the wrong schedule is
worse than no monitoring page. Change vercel.json and this follows
automatically.


TWO FAULTS THE TEST CAUGHT IN MY OWN PARSER
-------------------------------------------
I ran it against all 16 of your real schedules rather than a few I made up, and
it got two wrong:

  0 6,7 * * *     crm-daily-activities    read as UNKNOWN - a list of hours
  0 9 * * 1-5     variation-reminders     read as DAILY

The second was the dangerous one. That cron runs weekdays. Calling it daily
would report it OVERDUE every Sunday morning, for ever. An alert that cries wolf
weekly is an alert people switch off, which is worse than not having one.

Now: any day-of-week restriction is treated as weekly, which is the safe upper
bound, and a list of hours is still daily. All 16 read correctly:

    deliveries-sync   24h    crm-email-sync      0.3h
    hs-expiry-email   24h    crm-email-volume    24h
    weekly-report      1h    crm-call-volume     24h
    notifications     24h    gp-snapshot        744h
    design x4         24h    variation-reminders 168h
    hs-renewals        1h    crm-daily-activities 24h

    unreadable schedules: 0

A cron is allowed to be one full interval late plus an hour before it is called
overdue, so an 08:00 job is not flagged at 08:00:01 the next day.
