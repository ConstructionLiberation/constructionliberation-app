pkg922 - Email Notifications keeps the Admin navigation
========================================================

REPLACE (1 file, existing - no new files to create):

  pages/admin/notifications.js

DEPLOY AFTER pkg921, which created the shared <AdminTabs> this page now
uses. On its own it would not build.


WHAT WAS WRONG
--------------
The page built its own dark header and no tab bar at all, so opening it
dropped you out of the Admin navigation completely - the only way back was
the browser button.

It now uses AdminShell, the same wrapper every other Admin page uses, so the
header, the tabs, the highlight and the page width are identical to
Templates, Documents and the rest. Nothing about the notification builder
itself changed.


IT ALSO CLOSES A GAP - PLEASE READ
-----------------------------------
This page had NO ROLE CHECK. None. Any signed-in session could open the
notification builder and change what the business emails, to whom, and on
what schedule.

AdminShell gates it to admin, which matches who could reach it in practice:
the Email Notifications tab only ever appeared on Portal Users, and that page
redirects anybody who is not an admin.

If a management user has been using this page, they will now be redirected.
Tell me and I will widen the tab and the gate together.


AFTER DEPLOYING - CHECK
-----------------------
1. Admin, then Email Notifications. The nine tabs stay, with Email
   Notifications highlighted.
2. Every other tab is reachable from it.
3. The notification list and the editor work exactly as before.
