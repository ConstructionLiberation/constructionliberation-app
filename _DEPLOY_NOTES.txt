1. THE PLANNER ERROR YOUR EMAIL CAUGHT
--------------------------------------
    POST /api/planning
    Cannot read properties of undefined (reading '2026-09-25')

Clearing the LAST remaining day on a project. The handler does:

    delete alloc[key][date]
    if (!Object.keys(alloc[key]).length) delete alloc[key]    // project gone
    ...
    return res.json({ ok: true, day: alloc[key][date] || null })   // reads it back

When that day was the project's only one, alloc[key] is deleted and the line
below reads a date off an object that no longer exists.

AND IT THREW AFTER saveAlloc. So the change SAVED, and the person was told it
had failed. They reload, see it worked after all, and never mention it - which
is why this has never been reported despite being reachable any time somebody
clears a project's last day.

Found because the error email told us the route and the message. Without that it
would have needed somebody to notice and describe it.

I checked for the same read-after-delete pattern elsewhere in the file: the only
other candidate is an if/else where just one branch runs.


2. PRE-STARTS NOW SHOW IN COMPLETED FORMS
-----------------------------------------
They were never in that list. Pre-Start Minutes are not a Site App form - they
live at ops:prestart:{projectNo}, filled in from the project page, and nothing
ever wrote one into the submission index that Completed Forms reads.

lib/preStartDone.js already documents exactly this confusion, found from the
Forms Missing side:

    "Nothing ever writes a Pre-Start there, so that test could only ever return
     false."

This is the other half of the same gap.

They are PRESENTED in the list rather than stored as submissions - no duplicate
record, no migration of the ones already done, and one source of truth for a
Pre-Start.

DONE MEANS SENT, using isPreStartDone from that same file rather than a second
rule. A Pre-Start that has been saved but not issued does not appear, which
matches the Forms Missing page and the Monday chaser exactly.

If the lookup fails it is caught: a Pre-Start problem must not empty the
Completed Forms list.


3. FORMS MISSING: 50 PER PAGE
-----------------------------
Every required form for every project across the whole range came out in one
table. Previous/Next, with "Showing 1-50 of 312".

The page resets to 1 whenever a filter changes - otherwise changing a filter
could leave you on page 6 of a 2-page list, looking at nothing and concluding
there is nothing there.

Controls only appear when there is more than one page.
