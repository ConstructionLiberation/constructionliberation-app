PACKAGE 994 - the Glenigan cards stop being dated to Rock's history
================================================================================

Three files. Complete replacements. scorecard-crm.js includes 990's changes.

  pages/api/tenant-brand.js
  components/TenantProvider.js
  pages/scorecard-crm.js

NO RE-SEED NEEDED. This is code and one record field.


WHY ONLY TWO MONTHS HAD A LINE
================================================================================
pages/scorecard-crm.js line 66:

    const GLENIGAN_TRACKING_FROM = '2026-08-01'
    ...
    const measured = monthKey(GLENIGAN_TRACKING_FROM) <= m
    const gs = measured ? gleniganScored5 : null

Every month before August 2026 is marked UNMEASURED and returns null, which
the chart draws as nothing at all - not as a zero. So the card correctly
showed 2 and 8 for the only two months it considered measurable.

That date is the month ROCK started scoring Glenigan leads. Hardcoded in the
page, exactly like ESTIMATORS was, and meaningless on any other tenant.

Worth noting the gate itself is right and deliberate: the comment next to
Actively Chased says it was NOT gated and therefore "reported 0 for months
the CRM never measured", which is worse than reporting nothing. The fault is
the date being one customer's, not the gating.


THE FIX
================================================================================
gleniganTrackingFrom is now an optional field on the tenant record, carried on
/api/tenant-brand and read through useFormat(). The page falls back to the
'2026-08-01' constant when a tenant has not set one, so ROCK IS UNCHANGED -
it has no field, it keeps its date, and its charts look exactly as they do
today.

Both branches of the feed return the field, the no-tenant one as null. A field
present in one branch and absent in the other is how a client ends up reading
undefined and nobody notices for a fortnight.


ONE RECORD EDIT, ON tenant:demo
================================================================================
    "gleniganTrackingFrom": "2025-01-01",

Any date earlier than the seeded data will do - it means "we have been
tracking this the whole time", which for generated data is true. Then every
month on those two cards is measured and the chart draws across the full
range.

Leave it off and demo keeps Rock's August date, which is the behaviour you
just saw.
