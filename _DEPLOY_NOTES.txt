pkg875 - Read the control database credentials Vercel actually created
======================================================================

TWO FILES, neither new.
  lib/tenants.js
  pages/api/platform/tenants.js

Deploy this, then redeploy is all you need - no variables to copy by hand.


WHY
---
Creating the store through Vercel's Upstash integration with the prefix
CONTROL_REDIS produced:

    CONTROL_REDIS_KV_REST_API_URL
    CONTROL_REDIS_KV_REST_API_TOKEN
    CONTROL_REDIS_KV_URL
    CONTROL_REDIS_REDIS_URL

The code was looking for CONTROL_REDIS_URL and CONTROL_REDIS_TOKEN, which do not
exist. So nothing would have resolved and /platform would still have said "no
control database yet" after a correct setup - the most confusing possible
outcome.

Both spellings are now accepted, exactly as lib/db.js already accepts three
different spellings for Rock's database. Same pattern, not a special case.

The alternative was copying the values into a second pair of variables by hand.
That works until Vercel rotates the credentials and the copy silently goes
stale - and a stale credential on the control database means every customer
fails to resolve at once. Reading the name Vercel actually set has no such
failure.

REDIS_URL and KV_URL are the non-REST connection strings. Ignored - the app uses
the REST API throughout.

- grepped for CONTROL_REDIS everywhere else: only a help message, updated to
