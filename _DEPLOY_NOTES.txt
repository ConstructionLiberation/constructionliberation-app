PACKAGE 951 - the In Query project dropdowns were empty
================================================================================

One file. Complete replacement. Wipe and re-seed.

  lib/demoSeed.js


WHAT IT WAS
===========
Every row on the In Query tab offered "Not set" and nothing else, so a parked
cost could not be assigned to a job - which is the entire purpose of the tab.

Not an app bug, and not the data you could see. components/InQueryTable.js
makes its OWN fetch to /api/bookkeeping-inquery, separate from the four calls
pages/bookkeeping.js makes, and reads d.projects from it. That endpoint builds
the list with inqueryProjectOptions(), which reads

    projects:registry

which I had never seeded. Everything else on the page worked because it comes
from dashboard:cache, which was seeded - hence a tab full of correct lines
with a dropdown that had nothing in it.

Worth naming as a shape: THE PROJECT LIST EXISTS IN THREE PLACES and they are
not interchangeable.

    dashboard:cache      the commercial surfaces
    costs:lines:<id>     the WIP page
    projects:registry    the In Query dropdown, and anything that needs a
                         project to survive being deleted from Xero

Each was found the same way - a screen that was empty for no visible reason.


WHAT CHANGED
============
projects:registry is now written: 30 entries keyed by xeroId, each with name,
jobNo, trackingCategoryId, firstSeen and lastSeenInXero.

In Query is deliberately NOT in it. lib/inquery.js filters it out anyway,
since offering "In Query" as the answer to "which job is this In Query cost
for" is an own goal - the comment in that file says as much.

Added to the wipe list.
