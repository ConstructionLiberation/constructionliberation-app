4. A JOB THAT HAS STOPPED - a new nightly cron
----------------------------------------------
/api/cron/health-alert, 08:30 UTC, after hs-expiry-email at 08:00 so the
morning's jobs are judged on a fresh run rather than yesterday's.

It says NOTHING unless something is wrong.

A cron that has stopped cannot report that it has stopped. The absence is the
symptom, so something else has to notice. That is why this is a separate job
rather than a check inside each one.

vercel.json now has 17 crons, up from 16. You are on Pro, so no limit applies.


"NOT CONFIGURED" IS NOT A FAILURE - and this matters
----------------------------------------------------
crm-call-volume returns { ok: false, error: 'Not configured. Missing in Vercel:
EIGHTX8_...' } every night, because 8x8 has never been set up.

Without handling that, this package would have emailed you THE SAME THING EVERY
MORNING for as long as 8x8 stays on the backlog. An alert that always says the
same thing is an alert people stop opening - which costs you the one morning it
says something different.

So "not configured" is now its own status, shown on the page and never alerted
on. What actually alerts:

    crm-call-volume    not configured    silent
    wip-sync           not scheduled     silent
    gp-snapshot        never run         silent
    deep-sync          last run failed   EMAILS
    crm-email-sync     ok                silent

Only a job that has genuinely broken or genuinely stopped.


THE LOGIC MOVED TO lib/cronHealth.js
------------------------------------
It was inside the admin endpoint. Two things need it now - the page and the
alert - and two copies of "is this cron overdue" would drift. The copy that
drifts would be the alert, which would then quietly stop alerting: a monitoring
system that fails silently is worse than none, because it also removes the
worry that made you check manually.

pages/api/admin/cron-health.js is now four lines and returns what the library
computes. Its output is unchanged apart from the new status.
