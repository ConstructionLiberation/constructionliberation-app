*** THREE STEPS IN VERCEL - in this order ***
1. Storage -> Create -> Blob. Name it e.g. "rock-app-private" and choose
   PRIVATE access. Create.
2. Connect it to the project (Production and Preview) and set the environment
   variable PREFIX to  BLOB_PRIVATE  so the token is called
       BLOB_PRIVATE_READ_WRITE_TOKEN
   Check under Settings -> Environment Variables that the name is exactly
   that. (The existing BLOB_READ_WRITE_TOKEN stays as it is - it is the old,
   public store, still used by every existing upload.)
3. Settings -> Build and Deployment -> Node.js Version: 20.x or later (22.x is
   fine). The new library needs Node 20.
Then deploy this package (it includes package.json and package-lock.json).
Vercel's screens may word these slightly differently - the names above are
what matter. Until the token exists the Documents panels say "Private file
storage is not set up yet"; nothing else is affected.

WHERE DOCUMENTS ARE
  Estimate > Documents tab   documents for the whole estimate (compliance
                             documents etc.), or attached to one item
  The pop-out on an item     "Documents on this item" - e.g. the green roof
                             supplier's quote on the green roof rate
  Build-ups editor           "Documents on this build-up" - on the library
                             template itself
  + Add documents (several at once, up to 50 MB each); click a name to open;
  Delete. Archived estimates: read-only.

HOW THEY ARE KEPT PRIVATE
  - The store is private: files have no public address.
  - Uploads go straight from the browser to the store (no 4.5 MB limit), with a
    permission our server gives for THAT estimate / build-up's folder only,
    under the company's own folder - never another estimate's or company's.
  - Opening a file: the server checks the person's access, then sends the
    browser a link to that ONE file, read-only, that stops working after 5
    minutes.
  - The document lists are kept apart from the estimate, so an upload never
    collides with someone saving the take-off.
  - Deleting an estimate or a build-up deletes its files from storage; renaming
    a build-up (or its category) moves its documents with it.
  - The upload code (~230 KB) loads only when someone adds a document.

Checked (the route's rules, against a stand-in for the private store, since
this environment cannot reach Vercel):
  - not set up -> the list works and uploads say so plainly
  - upload permission: granted for the estimate's own folder (50 MB, random
    suffix so nothing is overwritten); refused for another folder, another
    company's folder, an archived estimate, an unknown estimate
  - register: refused if the file never arrived, sits outside the folder, or
    names an item not on the estimate; a 23 MB file recorded on its item
  - download: a redirect to a link scoped to that one file, read-only, 5 minutes
  - delete: gone from storage and the list; another company cannot reach the
    estimate's documents at all
  - with the REAL library installed, every page bundles for the browser (no
    new failures); the panel holds no server-only code
  - all server routes compile
