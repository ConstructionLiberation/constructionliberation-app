1. 8x8 IS GONE
==============
James has decided outbound call volume is not a feature that will be added.
Removed rather than left dormant, because a scheduled cron for an integration
that does not exist is noise with a slot attached.

The "Calls made" row is deleted from the sales scorecard, along with its
default target of 100/month. Deleted rather than kept as a manual entry: a
metric with no source either sits blank and looks broken, or invites a monthly
hand-count nobody maintains. Scorecards is due a proper pass anyway, and
reinstating something deliberately later is cleaner than leaving a stub.

>>> WATCH THIS ONE <<<

It is now FIVE and FIVE. That construct has caused faults here before - a
mismatch shifts every response one place along and the page renders plausible
nonsense rather than failing. Counted and commented in place. If the scorecard
shows wrong numbers after this deploy rather than no numbers, that is where to
look first.


2. THE CRON-HEALTH STATE THAT COULD NEVER FIRE
===============================================
This is why the alert arrived this morning:

  crm-call-volume - OVERDUE - last ran 30h ago - Not configured.
  Missing in Vercel: EIGHTX8_API_KEY, ...

lib/cronHealth.js already had a 'not configured' state, deliberately excluded
from alerts, with a comment explaining exactly why: an alert that always says
the same thing is an alert people stop opening.

But it was tested AFTER the OVERDUE branch. A job whose integration does not
exist never records a fresh heartbeat, so it is always overdue too - OVERDUE
always won, and 'not configured' was unreachable for precisely the jobs it was
written for. The state existed, was correct, and never ran.

Now tested before OVERDUE. Third instance today of the same pattern:

  pkg931  a tenant guard that never ran because the call was at module scope
  pkg932  fromEmail() that never ran because the env var was read first
  pkg933  a cron state that never ran because a broader test came first

WORTH ADDING TO CODE-NUANCES: when a guard is written for a specific case,
check that nothing broader upstream of it matches first. All three were correct
code in the wrong position.
