PACKAGE 1100 - Estimates save automatically

Two files. Complete replacements. No re-seed. No env changes. Built on 1099.

  pages/estimating/estimate/[id].js     (folder literally named [id])
  components/EstimatingShell.js         (its request helper reports the status code)

AUTOSAVE on every estimate - the take-off, the pop-out, settings, letter,
clarifications, materials: a change is saved about 1.5 seconds after the last
one. Beside the title:
  "Unsaved changes…" -> "Saving…" -> "All changes saved 22:59"
  "Not saved - retrying…"  (connection lost - it keeps trying, backing off)
  "Not saved - someone else saved this estimate since you opened it…"
     autosave STOPS - nothing of theirs is overwritten; Reload to see it
"Save now" saves straight away. Leaving with an unsaved change still warns.
  - Typing while a save is in flight is never lost: a save that lands keeps
    what is on screen and the newer edits go in the next save.
  - Issue / Download and mark as sent wait until the latest change is saved.
  - Archived estimates do not autosave (read-only).

Checked against the real routes with a deliberately slowed server: an edit
saved itself (250 stored); a description typed WHILE a 1.5-second save was in
flight stayed on screen and was stored by the next save (with qty 300); a
dropped connection showed "retrying" then saved (320); after someone else
saved, autosave stopped with the message, made no further attempts and their
change stayed; issuing straight after an edit waited for the save and Rev A
held the edit (777). All 165 pages pass the browser check.
