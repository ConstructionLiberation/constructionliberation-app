WHAT IT DOES
============
An "Edit tasks" button under the heading on all four checklist pages -
Commercial weekly and monthly, Bookkeeping weekly and monthly. Add, reword,
reorder, remove. Saves to the tenant's own database.

The pattern is the one pages/api/templates.js already uses for the Pre-Start
and IHM templates, and it is the right one: a CODE DEFAULT every tenant starts
from, an OVERRIDE in their own database, and the stored one wins. Nothing is
written until someone actually edits something, so a new customer inherits a
usable list rather than a blank screen, and Rock's lists are untouched until
somebody changes one.


WHY IT MATTERED
===============
The lists were literal arrays inside the components. Unmistakably Rock's:

  "Does the Retention Owed match 612 Allocated"     <- a Xero account code
  "Obtain the WIP schedule from Nathan"             <- a member of your staff
  "request Cotton to file VAT for the month"        <- your accountant

A customer would have been handed instructions naming an account they do not
have and people they have never met, with no way to change any of it.


DELETING DOES NOT DESTROY HISTORY
==================================
Ticks are stored against the task id in a separate key. Removing a task hides
it from the grid and leaves every tick alone - so deleting one by mistake
loses nothing, and re-adding the same id brings the history back.

That is also why an existing task's id is not editable: changing it would
orphan every tick ever recorded against it. New tasks get a generated id
prefixed by scope and cadence so a weekly and a monthly task can never
collide.


PERMISSIONS
===========
Reading: commercial, bookkeeping, post-contract, management, admin.
Saving: MANAGEMENT AND ADMIN ONLY - editing the checklist changes what
everyone else is asked to confirm each week.

The button is shown to everyone. A refused save explains itself more clearly
than a button that is silently absent.


ONE THING WORTH NOTING
======================
pages/api/task-definitions.js originally imported the defaults from
components/CommercialTaskTable, which dragged React, next/head and two nav
components into a server route. Moved to lib/taskDefaults.js instead. Worth
remembering as a shape: if an API route needs a constant that lives in a
component, the constant is in the wrong place.

Also: the page titles on these four pages said "Rock Roofing - ..." and now
just show the page name. The full branding fix for titles comes with the
client-side sweep.
