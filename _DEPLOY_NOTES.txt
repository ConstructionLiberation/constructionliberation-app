PACKAGE 996 - why the commercial data vanished, and why it would have done
              it again in front of WPC
================================================================================

28 files. One is NEW: lib/dashboardCache.js. The other 27 are one-line
changes - an import, and a call swapped.

RE-SEED AFTERWARDS to get the data back. This stops it happening again; it
cannot recover what has already gone.


WHAT HAPPENED
================================================================================
Nothing to do with time, and not a fault in anything you clicked. Twenty-eight
routes did this whenever something changed that would alter the commercial
figures:

    await redis.del('dashboard:cache')

pages/api/retention.js does it in FOUR places - including on saving a row.
contracted-rates.js, applications.js, variation-instruct.js and the upload
routes all do it too. Sweeping the commercial screens and saving anything was
enough.

On ROCK that is correct. The next Xero sync rebuilds the cache, and a stale
cache is worse than a missing one.

On DEMO it is destructive and permanent. pages/api/dashboard.js returns 401
before it ever reaches the cache when there are no Xero tokens - which is the
only reason a seeded cache works at all. Delete it and NOTHING can put it
back. Budget Tracker, Project Financials, Retention and WIP all go blank and
stay blank.

HANDOVER-6 wrote down half of this: "If the commercial pages go blank after a
change to dashboard.js, that function is why." The other half - that any of
twenty-eight routes could delete the cache outright - was never the danger on
a single-tenant app, because Rock always had Xero.


THE FIX
================================================================================
One function, lib/dashboardCache.js, and all 28 routes call it instead:

    await invalidateDashboardCache(redis)

It deletes the cache only if something can rebuild it. No accounting
connection, no delete. If it cannot even determine that, it also does not
delete - keeping a cache you were unsure about is recoverable, deleting one
you needed is not.

Checked both paths: with tokens it deletes, without tokens it skips. And
checked that `redis` is actually in scope at all 28 call sites, since the
replacement passes it as an argument where the old code closed over it.

One rule, twenty-eight places, now one place. Same shape as every other fix
this week.


WHY THIS MATTERED MORE THAN IT LOOKS
================================================================================
You found it by sweeping. On Friday, one save on a commercial screen in front
of WPC would have blanked the demo mid-sentence, with no way back inside the
meeting.


AFTER DEPLOYING
================================================================================
    wipe:  { action:'wipe', id:'demo', confirm:'demo' }
    seed:  { action:'seed', id:'demo', projects:30 }

Then the commercial screens come back, and stay back however much you click.


SMOKE TEST
================================================================================
1. Demo, after re-seeding: edit a retention row and save it. Budget Tracker
   and Project Financials still have data. That is the exact sequence that
   emptied them.
2. Demo: instruct a variation, save contracted rates. Same.
3. ROCK: change something on retention, then check the commercial pages
   refresh as they always have. The cache must STILL be dropped there - if
   Rock starts showing stale figures after an edit, that is this package and
   I want to know.
