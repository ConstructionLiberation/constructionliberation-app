PACKAGE 1227 - Contracted rates from an estimate: the quote's descriptions and
section headers

Two files. Complete replacements. No re-seed. No env changes. Built on 1226.

  lib/estimateToRates.js
  pages/contracted-rates.js

DESCRIPTIONS - each rate now carries the description AS THE QUOTE PRINTS IT:
the item's written build-up description (over its lines) when it has one,
otherwise its name - the quote's own rule, so the contracted rates read exactly
as the customer's quote did. The short name is kept with it.
SECTION HEADERS - each section of the estimate comes in as a HEADING in the same
place (above or below the line), bold and underlined - the way the quote prints
section headers (the estimate has no other style for them), and the Contracted
Rates default heading style. Applications carry headings and their formatting
on through, and labour schedules show them as headings. Spacers stay out (the
quote leaves them out too).
CONTRACTED RATES PAGE - a description's line breaks now show, and edit in a box
that keeps them (the single-line box used to lose them).
Rates already built from an estimate are not changed - use Delete & re-upload,
then Build from estimate again, to bring the descriptions and headings in.

Checked through the real route with a real estimate from Rock's library: the
section "Main roof" built as a heading above the line, bold and underlined; an
item with a written build-up description carries it over three lines, the
others their names - exactly what the quote prints; the totals and budgets
still equal the estimate's (811,200 / 7,000 / 24,200). In a REAL browser
(Chromium): the heading drawn bold and underlined; the description over its
three lines; editing it in a text box with the line breaks kept. All server
routes compile; all pages pass the browser check. Built from your deployed
packages (1022-1220) plus 1221-1226.
