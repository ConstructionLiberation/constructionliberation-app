PACKAGE 995 - hide the metrics a customer does not want
================================================================================

Two files. Complete replacements. scorecard-crm.js includes 990 and 994.

  pages/api/targets.js
  pages/scorecard-crm.js

No re-seed. Works on every tenant immediately.


YOUR IDEA, AND IT IS THE BETTER ANSWER
================================================================================
We were about to seed a number into "emails sent externally" so a card would
not look broken. That would have been inventing data to hide a gap. Hiding
the card says the truthful thing instead: this customer does not measure
that.

It also generalises past the three cards in front of us. Glenigan is a UK
data source a New Zealand contractor has never heard of. Actively Chased is
Rock's own lead category. Another customer will want measures neither of us
has thought of. A fixed list of metrics was always going to be wrong for
somebody.


HOW IT WORKS
================================================================================
A "Metrics" button sits at the right of the person tabs. It opens a row of
tick boxes - every metric for that scorecard - and unticking one hides it.
Saves immediately, no OK button. The button shows a count when anything is
hidden, so a hidden metric is never a mystery.

Stored per tenant as scorecard:hidden, an array of metric keys. Empty for
every existing tenant, so ROCK SEES NO CHANGE until somebody hides
something.

The filter is applied at ONE point:

    const metricDefs = allMetricDefs.filter(m => !hidden.includes(m.key))

metricDefs already fed all three renderers - the last-full-month cards, the
current-month cards and the trend table - so hiding a metric hides it in all
three. No second list to keep in step, which is the fault this codebase
produces more than any other.

Estimator and sales scorecards have separate metric sets and the picker shows
whichever you are on. The hidden list is shared, and the keys do not collide,
so hiding "total value of work priced" on one does not touch the other unless
the key is the same metric.


ONE THING IN THE API WORTH KNOWING
================================================================================
The POST used to be:

    await set('scorecard:targets', req.body.targets)

unconditional. A POST carrying only `hidden` would have written undefined
over every target the customer had set. It now writes each only if present.


NOT DONE, DELIBERATELY
================================================================================
pages/operations/scorecards.js has its own metric layout and is untouched.
Same idea applies there; it is a different page with fixed columns rather
than cards, so it is its own change.

And this hides metrics rather than adding them. Adding a measure we have not
written is a bigger piece - it needs somewhere to define how it is computed.


SMOKE TEST
================================================================================
1. Demo scorecard, sales tab: Metrics, untick Emails sent externally,
   Glenigan scored 5+ and Actively Chased scored 5+. The cards go, and so do
   their rows in the trend table at the bottom.
2. The button reads "Metrics (3 hidden)".
3. Reload - still hidden. It is stored, not local state.
4. Tick one back on: it returns, with its figures intact.
5. ROCK: the button appears, nothing is hidden, every card as before.
