DO STEP 1 BEFORE YOU DEPLOY
================================================================================
Set logoUrl on Rock's tenant record FIRST. It does nothing while the current
code is live, and if you deploy without it Rock's nav bar loses its logo and
shows the letters RR instead until you do.

In the Upstash console for the CONTROL database (control-registry), open the
key

    tenant:rock

and add one field to the JSON object:

    "logoUrl": "/rock-logo.jpg"

That is a real value, not a placeholder - type it exactly as written. The file
is in public/ and is served from every host, so the relative path is correct.

The registry is cached for 60 seconds and /api/tenant-brand sets a 60-second
browser cache, so allow about two minutes before it shows.

Do the same for tenant:demo if you have a demo logo. If you leave it unset,
demo renders its initials on a white square instead, which is a deliberate
fallback and looks fine - just never Rock's logo.


WHAT IT WAS
================================================================================
This exact line existed NINETEEN times across the codebase:

    <img src="/rock-logo.jpg" alt="Rock Roofing" style={{ height: 32, ... }} />

Four of those nineteen are in the nav components, and those four navs are
imported by forty-four pages between them. So on demo - on a
constructionliberation.com hostname - Rock Roofing's actual logo was rendering
in the nav bar of most of the portal.

Same shape as the login page found on 19 September, just further in. And the
same fault class as everything else this fortnight: logoUrl() has been
tenant-aware since pkg937 and had ZERO CONSUMERS. The guard existed, was
correct, and was never called.

Two shared shells were doing the same with the title tag:

    <Head><title>Rock Roofing - {title}</title></Head>

OperationsShell covers 25 pages, AdminShell 11. Both now read the tenant name.


WHAT IT IS NOW
================================================================================
components/BrandLogo.js is the single consumer of logoUrl(). It renders, in
order:

  1. feed not back yet    -> a transparent box of the right size
  2. tenant has a logo    -> the image
  3. no logo, has a name  -> initials on a white square (RR, CL, WPC)
  4. neither              -> the transparent box

The transparent box matters. Every page in the portal mounts one of these, and
a 32px element appearing a moment after paint shifts the whole nav row
sideways.

There is NO fallback to /rock-logo.jpg anywhere in it. A default that renders
somebody else's brand is the bug this file exists to remove.

Props: size (default 32), radius (default 4), style (merged, used for the
marginRight the Operations and Pre-Contract navs already had).

TWO THINGS FOUND ON A SECOND PASS, BOTH FIXED IN THIS ZIP
================================================================================
1. The placeholder box was a <span>, and an inline span IGNORES width and
   height. All five consumers today are flex containers, which blockifies
   their children and hid it completely. It now sets display: inline-block, so
   the sixth consumer does not get a box of nothing.

2. The portal home name line was {brand}, which is an empty string until the
   feed lands - an empty div is zero pixels tall, so "Company Portal" jumped up
   and back down on every load. It now renders a hard space while it waits.

Neither would have shown up in a compile, and the first would not have shown
up on any screen in the portal as it stands today.


CHECKED, NOT ASSUMED
================================================================================
- /api/tenant-brand does send both `name` and `logoUrl`. Read the feed, not
  the field name - that is the "client reads a field the feed never sends"
  fault.
- useFormat() is useContext(). In AdminShell it is placed ABOVE
  `if (!ok) return null`, not below it.
- TenantProvider wraps every page in _app.js, so there is no page where
  BrandLogo can mount without the context.
- esbuild compiles all eight clean, no warnings, and bundling each one for the
  browser pulls in nothing server-only.
- initialsOf() was RUN, not eyeballed: Rock Roofing Ltd -> RR, Construction
  Liberation Ltd -> CL, WPC Ltd -> WPC, Demo -> DE, empty -> empty. It briefly
  turned "Construction Liberation" into "LI" because the skip list had
  "construction" in it. Running it found that; reading it did not.
- public/rock-logo.jpg exists and is 565x565, i.e. square - so the objectFit:
  contain added to the img changes nothing for Rock. A WIDE wordmark logo
  would letterbox down to almost nothing inside a 32px square; that is a
  question for the logo upload screen, not for this package.
- No page passes a Rock-branded `title` into either shell, so fixing the two
  shells actually fixes all 36 pages.
- BizNav was in the plan and is NOT in this package. It carries no logo and no
  company name, so there was nothing to change.
