2. FOUR PDF SANITISERS THAT DISAGREED, AND ONE MISSING
------------------------------------------------------
pdf-lib's standard fonts use WinAnsi. Hand it a character outside that range and
drawText THROWS - the PDF fails, so the download fails, or the email that was
going to carry it never sends.

Five builders need the rule. What was actually there:

  applicationPdf   kept £, but replaced every ACCENTED character with a space
  variationPdf     kept £, same accent problem
  handoverPdf      DROPPED £ entirely (\\x20-\\x7E)
  weeklyLabourPdf  correct - kept everything Latin-1, plus a droplet rule
  preStartPdf      NONE AT ALL

So a name like Jose Nunez came out mangled on an application and on a variation -
documents that go to the customer. And a curly quote pasted into a Pre-Start
field made the send fail outright.

I reported earlier that variationPdf had no sanitiser. WRONG - it has one called
`san`, and my search looked for the word "sanit". Second time today a search
pattern produced a confident false answer. Both are corrected here.

Now one rule in lib/pdfText.js, used by all five. Tested across fourteen cases:

    pound sign            Total £1,234.56      kept
    curly apostrophe      James'               kept as '
    smart quotes          "Pre-Start"          kept as "
    em dash               J190 - Russell Hill
    ellipsis              and so on...
    non-breaking space    J190 Russell
    water droplet         WI: Leak at Gas Lane
    emoji                 removed
    accented name         Dori Balog, José Núñez   KEPT
    degree symbol         15°C on the roof         KEPT
    tick                  Y complete
    plain text            unchanged

    failures: 0     every output WinAnsi-safe: true

My first version of the shared rule turned "James' site" into "James site" - it
missed U+02BC, an apostrophe some keyboards produce, so it was stripped rather
than replaced. A DROPPED apostrophe is worse than a wrong one: nobody reads it
as an encoding problem, they read it as a typo we made. Caught by the test,
fixed, retested.


3. THE PRE-START WRITE MERGES INSTEAD OF REPLACING
--------------------------------------------------
pages/api/pre-start.js wrote { ...data } straight over the stored record, so
anything the client did not send back was erased - including sentAt,
sentManually, recipients and statuses, which are the PROOF a Pre-Start was
issued.

It has not bitten, because the autosave stops once the record is sent and both
save paths send a complete payload. But that is a guard in a DIFFERENT FILE
holding this one up. A third caller, or a change to that guard, and a Pre-Start
that was issued reads as never issued: it reappears in Forms Missing and the
Monday chaser emails the Contracts Manager about it again.

Same shape as the write that lost the Gas Lane application.
