pkg916 - CRM: clearing a customer contact's phone number actually clears it
============================================================================

REPLACE (2 files, both existing - no new files to create):

  pages/crm.js
  pages/api/crm.js

NOTE: same filename in two folders. Both must be replaced.


WHAT WAS WRONG
--------------
The delete was working. The redisplay was putting it back.

The Customer Contact panel falls back to the contact record whenever the
deal's own copy is blank:

    if (v != null && trim(v) !== '' && trim(v) !== '-') return v
    return dealContact?.[key] ?? ''

So clearing the phone wrote '' to the deal, that read as "nothing here",
and the contact record's number went straight back on screen. There was no
way to say "deliberately blank" - empty and cleared looked identical.

Writing through to the contact would not have worked either: upsert-contact
skips blanks on purpose, so a half-filled project form cannot wipe details
that came from the import. That guard is right and stays.


WHAT CHANGED
------------
1. New API action, clear-contact-field: blanks ONE named field on ONE
   contact. Explicit, so upsert keeps its guard. Refuses name, first_name
   and last_name - those identify the record, and blanking one orphans it.

2. Clearing a Customer Contact field on a deal now clears it on the contact
   record as well. The phone belongs to the person, not the deal, so it goes
   from every deal and from the Contacts page.

Setting a value is unchanged - it still writes to the deal only.


AFTER DEPLOYING - CHECK
-----------------------
1. Open the deal, clear the phone on Dan Kearney. It should stay cleared,
   with no refresh.
2. Reload the page. Still cleared.
3. Open another deal with the same contact - also cleared, which is the
   point.
4. Check the Contacts list - the number is gone there too.
5. Type a new number on a deal. It saves as before.


FOUND WHILE IN HERE - NOT FIXED, DIFFERENT AREA
------------------------------------------------
pages/api/crm.js imports sendTestMention from lib/crmMentions.js.
THAT FUNCTION DOES NOT EXIST - crmMentions exports six things and that is
not one of them.

SWC compiles a missing named import to undefined rather than failing, so it
builds and deploys clean. But the "send test mention" button on
pages/crm-scores.js calls action 'mention-test-send', which calls it, and
that throws a 500 every time.

Left out of this package deliberately - different area, and the fix needs a
decision about what the test send should actually do.
