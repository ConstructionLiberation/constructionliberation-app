PACKAGE 954 - a tenant with no Xero is not a failed cron
================================================================================

One file. Complete replacement.

  pages/api/cron/deliveries-sync.js


WHAT IT WAS
===========
deliveries-sync returned

    { ok: false, reason: 'not connected' }

when a tenant has no Xero tokens. lib/forEachTenant.js reads the BODY, not
just the status - so ok:false counts as a failed run. Demo has no Xero, and
correctly never will, so it produced a failed cron, an error email and a
cron-health alert every single day for a normal condition.

Seen within hours of demo being registered. This is the second instance of
exactly the same shape - pkg931 added msConfigured() to the email sync for the
same reason - and the reasoning is the same: an alert that fires for a normal
condition is an alert people stop reading, and then it costs you the one
morning it says something different.

Now returns { ok: true, skipped: true, reason: '...' }. `skipped` is the flag
forEachTenant ALREADY understands: it does not count as a failure and it does
not overwrite the heartbeat of a real run.


CHECKED THE OTHERS
==================
deep-sync and wip-sync also bail on missing tokens, but with a 401 - and both
are UNSCHEDULED (they are in the deliberately-unreachable list in
lib/cronHealth.js), so neither is looping tenants. deliveries-sync was the
only scheduled one with this shape.


NOT A FAULT, FOR THE RECORD
============================
Two of the three error emails you sent were historic: the
"PASTE_THE_HTTPS_URL" one is from yesterday's registry mistake, already fixed,
and the cron-health alert was reporting this same deliveries-sync failure.
