DEALS RESEARCHED
================================================================================
scorecard-crm.js counts it as:

    deals.filter(d => d.everIn1stContact && d.firstContactDate && ...)

Two TOP-LEVEL fields, not fields.*, and nothing set either - so the metric
was zero in every month on both the scorecard and the Sales Dashboard, which
deliberately share the source so they cannot disagree.

Now true for any deal that got past Project In, dated the day it moved, using
the same timestamp the history records for that step. So "deals researched"
and the deal's own history agree about when it happened.


LOST REASONS
================================================================================
Nothing was set, so every lost deal fell through to "No Reason Given" and the
chart had one bar.

The list is taken STRAIGHT FROM the lost_reason options in
lib/crmFieldSchema.js - checked programmatically, all eleven distinct values
are real options, so the dropdown on a deal offers exactly what the chart
shows. Inventing a reason here would have produced a value the select could
not round-trip.

Weighted the way a roofing pipeline really loses work:

    4/17  Price
    3/17  Roofing package already let
    2/17  Unable to make contact
    1/17 each  Package Contractor, Project Shelved, Alternative spec,
               Gone with preferred approved supply chain,
               Main Contractor didn't secure, No Time to Price,
               Lead Time, No Feedback Given

Only a LOST deal gets one. An open deal carrying a lost reason is the kind of
detail a prospect notices.
