THE SITE APP
================================================================================
The SRATs tile is replaced by Project Reports, and the new screen works
exactly as the SRAT one did:

  select a project  ->  + New project report  ->  the list for that project

Reports are editable, deletable and submittable. Everything written there is
the SAME RECORD the portal shows, in the same store, so a report started on
site can be finished at a desk and the other way round. A draft stays a draft
until Submit, and the card carries a Draft or Submitted pill.

One deliberate difference from the SRAT page: it does NOT cut the list off at
four weeks. A project report is a monthly document and last month's is the one
you most want to look at before writing this month's.


ONE AUTOFILL, NOT TWO
================================================================================
Pulling the variations, open issues and photos is fiddly - an open issue
reappears on every report until it closes and then shows once more; photos
come from submissions since the last report; an issue photo only counts if the
issue went to the customer.

That was 73 lines inside the portal page. It is now lib/projectReportAutofill.js
and both screens call it. Two copies of rules like those would have diverged
inside a month, and the divergence would have shown up as a report that
disagrees with itself depending on which device wrote it.

It also resolves the CUSTOMER and ADDRESS, because the portal's project list
and the Site App's name those fields differently (customer/address against
customer/location). Resolving it in one place means neither screen has to
know. The portal only takes them when the pull actually found them, so a
project the dashboard has no row for keeps what the list already supplied.


ALSO IN HERE - 1017 AND 1018
================================================================================
Editable report template: "Edit template" beside "+ Add new", showing the
WHOLE form with built-in rows greyed and your own sections in a gold-edged
block under Works completed. Free text / List / Photos, optional Required.

separate field so changing the project does not wipe them.

A report keeps the template it was written with, so editing the template never
alters a report already issued.


MIDDLEWARE

in pkg981. Everything else the new screen needs - dashboard, issues,
submissions, upload-photo - was already allowed.
