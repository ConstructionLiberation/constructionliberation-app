PACKAGE 967 - the Construction Liberation logo on demo
================================================================================

One file, and it is an IMAGE, not code.

  public/cl-logo.png

It cannot be pasted like the others. In GitHub use Add file -> Upload files
and drop it into the public/ folder.

No code change. BrandLogo has been reading logoUrl since 955 and there has
simply been nothing to read.


WHAT I DID TO THE FILE
================================================================================
Your original is 500x500 and 79 KB. It renders at 32px in the nav bars, 56
and 64 on the Site App home, and 74 on the financial pack cover.

Resized to 256x256 and quantised to 64 colours: 8.7 KB, which is a ninth of
the original and still sharper than anything on screen needs, including at
2x on a phone. The flat greens and the black survive quantisation without
banding - I checked a composite at 64px on both nav backgrounds rather than
trusting it.

Transparency kept. That matters and I checked it: the badge has its own
white disc inside the ring, so it reads on the dark nav (#1a1a19 and
#1a1a2e) AND on the white login card. A transparent logo with no disc would
have vanished on one or the other.

Worth noting for comparison: rock-logo.jpg is still 565x565 and 64 KB to
draw a 32px square, on every page of the portal.


THEN ONE RECORD EDIT
================================================================================
On tenant:demo in control-registry:

    "logoUrl": "/cl-logo.png"

A RELATIVE path is correct here, and I checked why rather than assuming.
Middleware rewrites almost everything on a siteapp.* host to /forms, which
would break a relative image - except there is an extension passthrough
covering .png, so /cl-logo.png is served on BOTH demo hosts. Rock's absolute
URL works for the same reason it always has, so nothing to change there.

Allow two minutes for the registry and feed caches.

   This is the one that proves the relative path works through middleware.
