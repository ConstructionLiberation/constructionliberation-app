THE MISMATCH (Apr-Sep, Existing Customer)
Sales Dashboard 46 decided, 17.1%; Business Scorecard 50 decided, 13.8%. The
difference was exactly four deals: 1157 60 New Later Living (Kori), J228
Farmstead V07 (Oakwood), 1347 Freestone Road (Watkin Jones), 1449 Val D'or
(Torsion). The dashboard labelled each deal when the enquiry CAME IN (a
hand-typed label winning); the scorecard judged it when the deal was DECIDED.
A customer whose first win landed between the two was Prospect on one and
Existing on the other.

THE RULE NOW - ONE LABEL PER DEAL, USED EVERYWHERE
  EXISTING CUSTOMER   we had already won a DIFFERENT project for that
                      organisation before the day THIS deal was WON or LOST
  PROSPECT            otherwise
  Open deals          judged as of today, so the label can change when the
                      deal is decided
  Typed by hand       IGNORED

Every existing-customer figure reads this one label from the deal:
  Sales Dashboard customer type (filter, breakdowns, detail)
  Business Scorecard: strike rate, value secured, value priced - existing
  Estimator cards: value priced - existing customers
So they agree by construction.

Value priced - existing customers now follows the deal's label too (it used the
date of each price change). A price change on a deal still open therefore
counts as existing if the customer is existing today - and can move once that
deal is decided. A value change whose deal no longer exists (an old Pipedrive
record) still uses the rule as at the change date.

WHAT WILL MOVE
The four deals above now count as Existing Customer on the Sales Dashboard as
well, so the dashboard's Existing Customer strike rate for Apr-Sep moves from
17.1% to the Business Scorecard's figure. Deals with a hand-typed Customer type
now show the calculated one instead.

Checked: the four-deal situation through the real code (enquiry before the

ignored; first win and never-won stay Prospect; open deal judged today);
dashboard and Business Scorecard identical; all earlier route tests unchanged
(pop-outs 80 metric-months 0 mismatches; average secured 0 mismatches); all 157
