TWO PROBLEMS, BOTH FIXED

1. THE DROPDOWN ONLY LISTED VALUES IT FOUND ON DEALS. No deal was "Existing
   Customer", so the option never appeared. The Sales Dashboard's Customer type
   filter now always offers the CRM field's three options: Existing Customer,
   New Customer, Prospect (plus All and Blank, as before).

2. NOBODY HAD FILLED THE FIELD IN, so every deal read "Prospect". A deal is now
   labelled automatically when the field is blank:

     EXISTING CUSTOMER  we had already won a DIFFERENT project for that
                        organisation before this deal came in (its created
                        date)
     PROSPECT           otherwise

   The same rule as the Business Scorecard. A value TYPED BY HAND on a deal
   always wins - nobody's entry is overwritten, including "New Customer" or a
   deliberate "Prospect".

   Organisation names are matched ignoring case and spacing. A deal with no
   organisation stays Prospect.

WHAT THIS CHANGES ON SCREEN
  Sales Dashboard   the Existing / New / Prospect breakdowns and the filter show
                    real splits for the first time; before, everything sat
                    under Prospect.
  Pre-Contract scorecard   "Value priced - existing customers" now uses the
                    Business Scorecard's rule exactly (organisation already won
                    before the date of each price change). It read the label
                    before, which was blank, so it showed zero against its
                    target. The two scorecards now agree.

The rule moved into its own small file (lib/existingCustomers.js) so the deals
code and the scorecards can both use it without loading each other.

Checked: the labelling (existing after a first win; prospect before it, on the
first win itself, and with no win; typed values kept); the existing-customer
scorecard tests unchanged; the Business Scorecard route unchanged (80
metric-months, 0 mismatches); affected pages and routes bundle; all 157 pages
pass the browser check.
