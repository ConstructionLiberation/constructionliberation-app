PACKAGE 932 - the environment was winning over the customer's sender
================================================================================

Eight files. Complete replacements. Nothing new to create.

  lib/designEmail.js
  lib/designRfiNotify.js
  lib/notifications.js
  pages/api/variation-instruct.js
  pages/api/chase-email-send.js
  pages/api/project-process.js
  pages/api/design-email-test.js
  pages/api/cron/variation-reminders.js


WHAT WAS WRONG
==============
Eight live send paths read the environment variable FIRST:

    const FROM = process.env.NOTIFY_FROM_EMAIL || fromEmail('forms')

NOTIFY_FROM_EMAIL is set, so fromEmail() NEVER RAN. The tenant-aware helper was
present, correct, and dead code.

Consequence for customer two: variation instructions, RFI notifications, design
emails, chase emails and project-process emails would all have gone out FROM
ROCK ROOFING'S ADDRESS, off Rock's verified sending domain, with the customer's
own domain sitting unused in Resend.

pages/api/chase-email-send.js was the worst of them - it read
ACCOUNTS_FROM_EMAIL and then fell through to a HARDCODED
"Rock Roofing Accounts <onboarding@resend.dev>". A second customer chasing
their own debt would have done it in Rock's name.

Same shape as pkg931: a guard that exists, is correct, and never executes. And
the same root pattern as the seeded CRM deals - a default that looks right
because it happens to be the first customer's value.


WHAT CHANGED
============
Every site now calls fromEmail(kind) and nothing else. fromEmail() already
carries the same environment chain as its no-tenant fallback, so SINGLE-TENANT
BEHAVIOUR IS UNCHANGED - the precedence was the entire bug.

Kinds were chosen to preserve exactly what each site resolved to before:

  lib/designEmail.js            FORMS_FROM_EMAIL  ->  fromEmail('forms')
  lib/designRfiNotify.js        FORMS_FROM_EMAIL  ->  fromEmail('forms')
  lib/notifications.js          NOTIFY_FROM_EMAIL ->  fromEmail('notify')
  variation-instruct.js         NOTIFY_FROM_EMAIL ->  fromEmail('notify')
  variation-reminders.js        NOTIFY_FROM_EMAIL ->  fromEmail('notify')
  project-process.js            NOTIFY_FROM_EMAIL ->  fromEmail('notify')
  chase-email-send.js           ACCOUNTS_FROM_EMAIL -> fromEmail('accounts')
  design-email-test.js          reports fromEmail('forms'), which is what
                                designEmail.js actually uses. The diagnostic
                                was reporting a different value from the one
                                the code used.

Note the kind changes on the two design files: they were passing 'notifyOnly'
but the env read in front meant FORMS_FROM_EMAIL was what actually went out.
'forms' preserves the real behaviour rather than the written intent.


DELIBERATELY NOT CHANGED
=========================
lib/errorReport.js still reads ERROR_REPORT_EMAIL / NOTIFY_FROM_EMAIL globally.
Platform errors go to the platform operator, not to the customer, so a global
value is arguably right. Flagged in OUTSTANDING-5 as a decision to take rather
than an oversight.

pages/api/design-email-test.js lines 21-22 still report the raw environment
values. That is legitimately what those fields are for - they show what is
configured. Line 24 is the one that had to change, because it claimed to show
what the code uses.
