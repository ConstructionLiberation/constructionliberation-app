PACKAGE 1002 - Operations Scorecards stop being Will, Mike and Dori
================================================================================

Three files. Complete replacements. OperationsShell includes 966's change.
No re-seed - this reads the tenant's own people.

  pages/api/ops-scorecards.js
  pages/operations/scorecards.js
  components/OperationsShell.js


WHAT WAS THERE
================================================================================
    const SUB_TABS = [
      { key: 'will', label: 'Will', kind: 'cm', name: 'Will' },
      { key: 'mike', label: 'Mike', kind: 'cm', name: 'Mike' },
      { key: 'dori', label: 'Dori', kind: 'ops', name: 'Dori' },
    ]

and a heading reading "Contracts Managers (Will & Mike) and Operations Manager
(Dori)." Three tabs for people who do not exist on any other tenant, each
matching no projects.


THE NAMES WERE ALREADY THERE
================================================================================
/api/ops-scorecards has ALWAYS returned `cmNames`, built from the Contracts
Manager actually set on each project. The page ignored it and used the
hardcoded list instead. That is the whole fix for the CM side - no new data,
no configuration.

The ops series had no name because there was only ever one Operations Manager
and everybody knew who. The route now also returns `opsNames`, taken from
portal users whose job role is Operations Manager - the tenant's own people.
More than one is fine; they share the one ops series, which is what that
series measures anyway.

Same approach as pkg988 on the pre-contract scorecard: derive from the data
rather than configure, so the list cannot drift from what the metrics filter
on.


THE ROLE UNDER THE NAME
================================================================================
As you asked, and matching the pre-contract tabs. SubTabs gained an OPTIONAL
second line: pages/operations/projects.js passes no `sub`, so its tabs render
exactly as before - checked, it is the only other caller.


THE STATE NOBODY HAD TO THINK ABOUT BEFORE
================================================================================
`current` can now be NULL - a customer on day one with no Contracts Manager
set on any project and no Operations Manager in their people. Previously
impossible, because the list was hardcoded and always had three.

Guarded at every use rather than assumed, and there is an empty state that
says where the two lists come from, so somebody can go and fix it rather than
wonder why the page is blank.
