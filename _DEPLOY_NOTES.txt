pkg895 - The cold-snapshot report. Spreading a request does not copy it.
========================================================================

ONE FILE.  pages/api/project/[id]/report.js  (literal square brackets)

REPLACES the pkg894 version. Deploy pkg894 first if you have not - it has the
error-email changes - then this over the top.


WHAT HAPPENED
-------------
You cleared the cache and downloaded a report. It said:

    Could not build the financial data for this report.

The rebuild ran, produced nothing, and could not say why. Three layers between
the cause and the message.


THE CAUSE
---------
pkg894 called the dashboard handler directly instead of over HTTP - right idea -
and passed it a copy of the request:

    await dashboardHandler({ ...req, method: 'GET', query: {} }, fakeRes)

{ ...req } LOOKS LIKE IT COPIES THE REQUEST AND DOES NOT.

On a Node IncomingMessage, `headers` is a GETTER ON THE PROTOTYPE. Spread copies
only own enumerable properties, so the copy had no headers at all. Demonstrated:

    const req = new http.IncomingMessage()
    req.headers = { host: 'app.rockroofing.co.uk' }
    ({ ...req }).headers        ->  undefined
    ({ headers: req.headers })  ->  present

So withTenant saw no host, resolved no customer, and returned 404 Unknown
address - which my code read as "no projects" and reported as "could not build
the financial data".

The tenant check worked perfectly. It refused a request with no address, exactly
as designed. It was my request that was broken.


THE FIX
-------
The inner request is now built explicitly - method, query, url, headers,
cookies - rather than spread. Checked: this pattern appears nowhere else in the
codebase.


ALSO: THE FAILURE NOW NAMES ITSELF
----------------------------------
The rebuild produced nothing and returned a flat 503. The dashboard has three
different failure replies - 401 not connected to Xero, 500 with a message, or
genuinely no projects - and they need completely different responses.

If it fails again the error now says which, with the status code and the
dashboard's own message. Guessing between them from a screenshot is how an
evening disappears.


CHECKS I RAN
------------
- esbuild compile: 0 errors
- import-graph check: clean
- ran the spread against a real IncomingMessage to confirm headers are lost
- grepped for { ...req } elsewhere: nowhere else
