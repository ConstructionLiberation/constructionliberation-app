pkg887 - Error reporting, both halves. REPLACES pkg886.

DEPLOY BEFORE pkg885. pkg885 makes routes throw; this is what tells you.


WHAT pkg886 MISSED, measured
----------------------------
pkg886 caught routes that THROW. Then I counted what that leaves:

    148 places across 105 files return a 500 deliberately
        res.status(500).json({ error })   - no exception, so no catch sees it

    287 silent catches in pages and components

Graceful failure is the COMMON case in this codebase, not the rare one. So
pkg886 would have covered the crashes and missed most of the quiet failures -
which are precisely the ones nobody reports.


1. ANY 5xx IS REPORTED, thrown or returned
------------------------------------------
withTenant now checks the status code on the way out as well as catching
exceptions. All 148 deliberate 500s are now heard.


2. BROWSER ERRORS ARE REPORTED
------------------------------
components/PageErrorBoundary.js already caught render failures and showed them
on screen. That fixed the DIAGNOSIS problem - the person looking can see what
went wrong. It did nothing for DETECTION: they refresh, work around it, and say
nothing. A page that white-screens for one person on a Tuesday was invisible.

It now also posts to /api/client-error, which hands it to the same reporter.

That endpoint is deliberately minimal and deliberately open:

  - NOT wrapped in withTenant. A page that broke BECAUSE a customer could not be
    resolved must still be able to say so.
  - NO session required, and added to middleware's open list. A page that breaks
    during sign-in would otherwise be silent - and after pkg880, a stale session
    being rejected is a thing that happens.
  - Touches no database. Returns 204 whatever happens. A page that has already
    broken must not then have to handle a failure from the thing reporting it.

The customer is taken from the ADDRESS rather than resolved, so the email still
says which site it happened on without depending on the registry.


WHAT YOU GET
------------
    Portal error: /api/wip                        a server failure
    Portal error: [browser] https://app.../wip    a page that broke in the browser

Both to ALERT_EMAIL, throttled per route and message for 30 minutes.

- esbuild compile on all 5: 0 errors
