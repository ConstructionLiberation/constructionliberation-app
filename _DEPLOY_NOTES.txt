PACKAGE 939 - "Portal Portal", and two guards that should have been there
================================================================================

Five files. Complete replacements. Nothing new to create.

  pages/api/tenant-brand.js
  pages/api/admin/tenant-setup.js


1. WHY THE LOGIN PAGE SAID "PORTAL PORTAL"
===========================================
/api/tenant-brand was not in the middleware allowlist of routes reachable
without a session. So on the login page - which by definition has no session -
the fetch got a 401, the provider fell back to its defaults, and the heading
rendered `{brand} Portal` with brand = "Portal".

My miss, and the rule was already written down: ANY NEW API ROUTE MUST BE ADDED
TO THE MIDDLEWARE PASSTHROUGH. I wrote a route whose entire purpose is to work
before sign-in and then did not open it.

Two lines added:
  - the anonymous allowlist (so the login page can read it)
  - the external-user gate from pkg929 (so the Design portal nav can too)

It is safe to open because the response is enumerated field by field and
carries only what is already public: name, logo, locale, currency, terms. No
modules, no hosts, no addresses.


2. THE FAILURE MODE ITSELF
===========================
The fallback name was the word 'Portal'. A placeholder that reads as real
content composes into nonsense at the call site - hence "Portal Portal" rather
than something obviously broken.

It is now an empty string, in both the provider and the API's unresolved
branch, and the login page decides its own fallback:

  {brand ? `${brand} Portal` : 'Portal'}

So a feed that fails now shows a missing name rather than a wrong one.


3. register NOW REFUSES A URL THAT IS NOT A URL
================================================
Yesterday a register call went through with the literal string
"PASTE_THE_HTTPS_URL" in redis.url. It returned ok:true, the tenant looked
registered, and every request to that hostname then threw "Upstash Redis client
was passed an invalid URL". A broken tenant created by a successful-looking
call.

register now checks redis.url starts with https:// and has a dot in it, and
that redis.token is at least 20 characters, before writing anything. Same
principle as first-admin checking the password length: validate at the door
rather than discover at the first request.

The error messages name what was received, truncated to 40 characters, so a
pasted placeholder is obvious without echoing a real token.
