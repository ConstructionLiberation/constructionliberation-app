WHAT CHANGED FROM 1017
================================================================================
The editor listed only the sections you had added, which made it a list of
boxes rather than a form. It now shows the WHOLE report in order:

    Date                                   built in
    Project                                built in
    Customer company                       built in
    Your name                              built in
    Project address                        built in
    Variations          (pulled)           built in
    Issues              (pulled)           built in
    Site communications                    built in
    Works completed                        built in
      |
      +--  your sections, editable, in a gold-edged block
      |
    Photos              (auto-collected)   built in
    Additional photos   (added manually)   built in
    Approval                               built in

The built-in rows are greyed, marked "Built in", and show a note where the
content comes from somewhere else - Variations and Issues are pulled from the
project, Photos are auto-collected. They cannot be edited or moved: they are
the report.

Your own sections sit in position under Works completed, inside an indented
block, with add / reorder / remove acting only on them. Seeing them beneath
"Works completed" rather than in isolation is the whole point - it is the
difference between editing a form and editing a list.


WHERE THE FIXED LIST LIVES
================================================================================
lib/projectReportTemplate.js, as BUILT_IN_SECTIONS, with CUSTOM_AFTER naming
where the editable block sits. It exists ONLY so the editor can draw the form;
nothing renders a report from it and nothing stores it.

Worth knowing it is therefore a SECOND description of the report's structure -
the first being the form itself. If a built-in section is ever added, renamed
or moved, this list needs the same change or the editor will show a form that
no longer exists. There is a comment saying so at the top of it.

I considered deriving the list from the form instead, which would remove the
duplication. It is not worth it: the form is JSX with conditional blocks and
inline labels, and parsing it would be far more fragile than keeping twelve
lines in step.


EVERYTHING ELSE IS AS 1017
================================================================================
- "Edit template" next to "+ Add new"
- Free text / List / Photos section types, with an optional Required flag
- A report keeps the template it was written with, so editing this does not
  alter any report already issued
- Manual photos stored separately from the auto-collected set, so changing
  the project does not wipe them
- One drawPhoto() in the PDF, used by the Photos block and every custom photo
  section
- Reading the template: anyone who writes reports. Changing it: management
  and admin.


SMOKE TEST
================================================================================
1. Report tab, Edit template: the full form is listed, built-in rows greyed,
   with a gold-edged block under Works completed.
2. Add a free-text section and a photos section. They appear inside that
   block, in order, and nowhere else.
3. The arrows move your sections within the block only; the first cannot move
   up and the last cannot move down.
4. Save, then create a report: the sections appear under Works completed, in
   the same order the editor showed.
5. Download the PDF - same order, list sections as bullets, custom photos
   under their own heading.
6. Rename a section, reopen a report saved earlier: it must still show the
   OLD heading.
