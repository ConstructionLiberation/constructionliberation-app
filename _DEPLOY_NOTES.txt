THE PORTAL AND THE SITE APP TOOK PROJECTS FROM TWO PLACES - the portal from
the dashboard's Xero projects, the Site App from its own (IHM) project list,
matched to Xero by an exact job number. Names could differ, and a Site App
project with no exact Xero match was saved with NO Xero project - invisible
now, but it would break committed costs, writing POs to Xero (stage 3) and
bill matching.
NOW ONE LOOKUP (lib/poProjects.js) for both:
  - a PO is always tied to the XERO project - its id, job number and name come
    from Xero, set on the server (never from the page)
  - the Site App still decides WHICH projects an operative sees (their access,
    live projects), each matched to Xero by job number - tolerantly (J228 =
    228 = j228), the same rule the IHM lookups use
  - a Site App project with no Xero project is shown GREYED: "not set up in
    Xero yet, ask the office" - no PO can be raised against it
  - Purchase Orders list (office): "Live Site App projects not set up in Xero:
    J232 ..." and "N purchase orders not linked to a Xero project" with
    "RELINK BY JOB NUMBER" (management / admin) - links each to the Xero
    project of the same job number and reports any it cannot match.

AFTER DEPLOYING: open Purchase Orders - if the notice shows, fix the job
numbers in Xero (or the IHM) and press Relink.
