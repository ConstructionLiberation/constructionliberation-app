PACKAGE 1022 - four metrics off the Contracts Manager scorecard
================================================================================

Three files. Complete replacements. No re-seed. No env changes.

  pages/operations/scorecards.js
  pages/api/ops-scorecards.js
  pages/api/targets.js


WHAT CHANGED
================================================================================
Removed from the Contracts Manager scorecard, by decision:

  - H&S incidences
  - Water Ingress - Rock at fault
  - Procurement savings complete
  - Issues resolved on time

Left as they were:

  - Gross margin - their projects
  - Pre-Start Notifications

The Operations Manager scorecard is untouched.

The cards and the trend table both come from one list, so they go from both
at once.


THE ROUTE STOPS COMPUTING THEM TOO
================================================================================
Hiding the cards only would have left the server doing the work on every
load. Those four were the only reason /api/ops-scorecards:

  - read the whole submission index,
  - then fetched every accident, water ingress and pre-start submission in
    full, one read each,
  - then read the procurement savings doc for every closed project, once per
    Contracts Manager.

All of that is gone. Pre-Start % never used those reads - it comes from the
forms-missing rows - so it is unaffected.

Worth having while the Upstash bandwidth cause is still unknown: this page
was making a read per submission of those types, every time it opened.


TARGETS
================================================================================
The four targets are removed from the DEFAULTS in /api/targets, which only
matters for a tenant that has never saved a target.

Rock's saved targets still hold the four values. They are harmless - nothing
reads them now - and are left in place rather than rewritten, so nothing is
lost if a metric ever comes back.
