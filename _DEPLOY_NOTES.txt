PACKAGE 1024 - Operations Scorecards: two metrics off, Toolbox Talk by month,
               percentage targets
================================================================================

Three files. Complete replacements. No re-seed. No env changes.

DEPLOY 1022 AND 1023 FIRST. All three files here are built on those versions.

  pages/operations/scorecards.js
  pages/api/ops-scorecards.js
  pages/api/targets.js


1. REMOVED FROM THE OPERATIONS MANAGER SCORECARD
================================================================================
  - Tasks completed on time
  - Risk log completed on time

Cards and trend table both. The route no longer reads the live tasks or the
risk log - those two metrics were the only reason it did. Defaults removed
from /api/targets; Rock's saved values are left in place, unread.


2. TOOLBOX TALK - ANY MONTH, ON A GRAPH
================================================================================
Before: Yes/No buttons that only ever set the LATEST month, and no graph.

Now:
  - The card has a month picker (latest first) beside Yes and No. Pick a
    month, click Yes or No. Clicking the button that is already lit clears
    that month back to "not set".
  - The card draws the line graph like the others: Yes plots at the top, No
    at the bottom, unset months are skipped. Same trend line.
  - In the trend table, each Toolbox cell is clickable:
    not set -> Yes -> No -> not set.

Clearing deletes the stored value rather than writing null. The twelve month
reads now run in parallel instead of one after another.


3. PERCENTAGE TARGETS - 30 MEANS 30%
================================================================================
Targets are stored as fractions (1 = 100%). The box saved exactly what was
typed, so 30 became 30 and showed as 3000%.

Now, on percentage metrics:
  - the box opens showing the target as a percentage (100, not 1)
  - a % sign sits beside it
  - 30 or "30%" saves as 30%
  - anything that is not a number is refused, with a message, instead of
    being stored as text

A failed save now shows the server's message and puts the old target back.
Previously the screen showed the new value whether or not it saved.

ANY TARGET ALREADY SHOWING 3000% (or similar) needs re-typing once. Nothing
converts the old values automatically - a stored 30 could mean 3000% typed by
mistake or a real count, and only you know which.


NOT IN THIS PACKAGE
