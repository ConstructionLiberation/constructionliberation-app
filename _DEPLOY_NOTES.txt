PACKAGE 944 - the money columns, WIP, and retention release dates
================================================================================

One file. Complete replacement. Wipe and re-seed after deploying.

  lib/demoSeed.js


1. WHY EVERY MONEY COLUMN SHOWED A DASH
========================================
Total Spend was correct while Invoiced, Retention, Lab Spend and Mat Spend all
showed dashes. That inconsistency was the clue: Total Spend comes from the
cache row, so the row was fine and the other columns were reading something
else.

They read the row too - just five fields I never wrote:

    p.grossInvoiced          p.retentionOutstanding    p.remainingToClaim
    p.labourSpend            p.materialsSpend

pages/commercial.js renders those DIRECTLY in the default Budget Tracker view.
The derived calcAtValDate() path - which does compute them from _costLines and
_invoiceLines - only runs in EOM Report mode. I had spent the last package
making the line-level data correct for a code path the page was not using.

All five are now set, consistent with the lines beneath them.


2. WHY WIP WAS EMPTY
=====================
"No WIP to show for August 2026. Projects appear here when there are
post-valuation costs."

Exactly right, and there were none. Cost lines were dated randomly across each
project's life, so almost nothing landed after the current valuation date.

Live projects now get 2-7 cost lines dated deliberately in the last 26 days.
21 of 30 projects now have post-valuation costs, so WIP calculates and the
month-end figure is non-zero.

That is also more realistic: work continues after the valuation is cut, which
is the entire reason WIP exists.


3. RETENTION HAD NO RELEASE DATES
==================================
"30 retentions with no release date - these never show as overdue and never
reach the Cash Flow."

There was no retention:entries key at all - the tracker was deriving rows from
the projects with nothing to release. Now written properly: 30 entries with
customer, project, final account, percentage, certified value, and BOTH
release dates. First release a month after PC, second a year after. Six are
past due and unpaid, so the overdue state and the cash-flow schedule both have
something in them.

retention:entries added to the wipe list, so re-seeding stays clean.
