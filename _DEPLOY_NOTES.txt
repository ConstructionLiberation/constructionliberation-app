PACKAGE 1014 - a variation can be un-instructed
================================================================================

One file. Complete replacement. Includes 999. Mind the folder and brackets.
Rock-live behaviour change, no re-seed.

  pages/api/project/[id]/settings.js


THE PROBLEM WITH THE OLD LOCK
================================================================================
An instructed variation could not be changed - including being corrected. Mark
one instructed by mistake and the lock refused every subsequent save, the one
that would have fixed it included. The only way back was editing the stored
record directly.

A control nobody can undo is a trap rather than a control.


WHAT IS ALLOWED NOW
================================================================================
The single transition instructed -> not instructed, PROVIDED nothing else
moves in the same save:

  un-instruct, nothing else changed        allowed
  un-instruct AND reprice in one save      REFUSED
  reprice while still instructed           REFUSED
  no change at all                         allowed

So you cannot quietly un-instruct and re-price in one step. Clear the flag,
then edit - two deliberate actions, both visible. The lock on an instructed
variation's figures is untouched.

The refusal now tells you the way out: "...cannot be changed while it stays
instructed. Un-instruct it first if the instruction was logged in error, or
raise a new variation."


ONE THING THAT WOULD HAVE BITTEN
================================================================================
The comparison normalises to trimmed strings rather than using
JSON.stringify. The edit modal writes varNumber: form.varNumber, so a
variation stored WITHOUT that field comes back as '' - identical to a person,
different to JSON.stringify, and it would have refused an un-instruct that
changed nothing real. Exactly the shape of the "undefined has been instructed"
fault in 999.

Checked both save paths: the inline Instructed dropdown on the tracker, and
the edit modal. Both now go through.


NOT CHANGED
================================================================================
Deleting an instructed variation is still refused. That is a different act
from correcting a flag and should stay deliberate.

And the tracker's inline dropdown already checked its response and alerted on
failure, so refusals from this guard have always been visible on that path -
unlike the edit modal, which 1009's sibling problem still applies to.


SMOKE TEST
================================================================================
1. ROCK: find an instructed variation. Set the row's dropdown to Not
   Instructed. It saves.
2. Now edit its value. That works too, because it is no longer instructed.
3. Mark it instructed again, then try to change the value - refused, with the
   new message naming the variation.
4. Open the edit modal on an instructed variation, set Instructed to No and
   save without touching anything else. It saves.
