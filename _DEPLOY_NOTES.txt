WHAT I MISSED
================================================================================
957 said "the server side of the same screen". It did the weekly report EMAIL
BODY and not the PDF ATTACHED TO IT, which has its own module-scope formatter
at line 13, hardcoded en-GB/GBP, with a literal '£0.00' as its NaN case.

So on demo the mail would have said $ and the attachment £, on the same send.
Same mistake shape as the one before it: I checked the file I was editing
rather than every output path off that screen.

Now reads money() from lib/locale.js, like the report body. The NaN case still
returns a formatted zero rather than an empty cell, which is what the old one
did.


CHECKED
================================================================================
- Standard PDF fonts use WinAnsi, and this file already strips anything
  outside it. Ran the four locales: en-GB gives U+00A3, en-NZ, en-AU and en-US
  all give a plain dollar sign at U+0024. Everything inside WinAnsi, so no
  currency symbol can come out as a blank in a PDF.
- Compiles clean.
