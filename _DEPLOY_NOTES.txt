PACKAGE 999 - "Refused: undefined has been instructed"
================================================================================

One file. Complete replacement. Mind the folder and the brackets.

  pages/api/project/[id]/settings.js

NO RE-SEED. Code only - your contracted rates, applications and retention
ticks are untouched.


WHAT WAS HAPPENING
================================================================================
Saving ANY project detail - a customer contact, an address, a valuation day -
runs a lock that protects instructed variations from being altered. Correct,
and it is the control rather than the screen, as the comment there says.

It matched variations on varNumber alone:

    incoming.variations.find(v => String(v.varNumber || '') === String(was.varNumber || ''))

A variation with no varNumber gives an EMPTY string, so every numberless
variation matched the FIRST one in the list. Its signature then differed from
all the others, and the save was refused - naming "undefined" because there
was no number to name.

The seeded variations carry `id` and `ref` (V01, V02) but no varNumber, which
is why it showed up on demo. It is not a demo-only shape: anything written
without a number behaves identically on any tenant, and matching the WRONG
variation is a good deal worse than refusing the save.


THE FIX
================================================================================
Matching now uses the same composite key the drop-check two lines above
already uses - varNumber plus description. Demonstrated rather than reasoned
about: with the old rule V02 resolved to V01; with the new one it resolves to
V02.

And the refusal now names something. varNumber, else ref, else the
description. "Refused: undefined has been instructed" told you nothing and
told me nothing either - it took reading the source to find out which check
had fired.


WHAT IT DOES NOT CHANGE
================================================================================
The lock itself. An instructed variation still cannot be altered or removed,
and Rock's variations carry varNumber so they match exactly as before - the
composite key adds the description, which is identical on both sides for an
unchanged variation.


SMOKE TEST
================================================================================
1. Demo: open a project, Edit Project Details, add a customer contact, save.
   It saves.
2. Demo: change the valuation day or the address. Saves.
3. ROCK, the one that matters: find a project with an INSTRUCTED variation,
   try to edit that variation's value in Edit Project Details, and confirm it
   is still refused - and that the message now names the variation. Then
   change something unrelated on the same project and confirm it saves.
