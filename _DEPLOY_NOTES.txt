WHAT WAS WRONG
==============
The rows appeared; the figures did not. Five separate shape mismatches, all
from me guessing field names instead of reading the consumers. Each one found
by reading the page that renders it:

1. COST LINES used `account` and `total`.
   pages/commercial.js reads l.accountCode and l.amount. Every money column
   came out as zero while the project rows themselves showed. Now both sets of
   names are written.

2. INVOICE LINES used `total`.
   Invoiced is read as `sales200`, falling back to `subTotal`. `total` alone is
   invisible. Now all three.

3. THE AFA FIELD was `afaGross`. The Commercial table reads `afa`. Both set.

4. ops:projects WAS FLAT. The real shape is
   { projectNo, status, manual, createdAt, updatedAt, data: { projectName,
   customerCompany, projectAddress, contractsManager, estimator,
   quantitySurveyor, designManager, operationsManager, ... } }
   A flat object gives a project list with every column blank - which is why
   Operations and Design looked empty.

5. crm:deals USED `stage` AND TOP-LEVEL ATTRIBUTES.
   pages/crm.js reads deal.stageId, and every attribute out of deal.fields -
   51 references to d.fields in that one file. A deal with its values at the
   top level renders as an empty row. Stage ids must also be real:
   stage_project_in, stage_received, stage_mc_secured and so on. Fixed, with
   the full CRM field set populated: organization, contact_person,
   contact_email, contact_phone, contact_job_role, org_address, org_phone,
   org_website, value, site_location, region, size_m2, credit_score,
   credit_limit, estimator_responsible, project_type, lead_source,
   project_start_date, scope_of_works, supply_chain_approved.
