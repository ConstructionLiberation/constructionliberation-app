PACKAGE 1108 - Decimals can be typed everywhere; rates shown to 2 decimal places

Three files. Complete replacements. No re-seed. No env changes. Built on 1107.

  components/BuildupEditor.js
  pages/estimating/estimate/[id].js     (folder literally named [id])
  pages/estimating/price-list.js

FIXED: a number under 1 (e.g. an own item at 0.25) could not be typed. Every
number box turned each keystroke into a number, so "0." became 0 and the
decimal point vanished. The same fault was in Width / Height, lump amounts,
waste %, price increase %, and on the estimate: Profit %, MCD % (2.5 could
not be typed), labour factor, day rate and an item's profit %. All now use one
number box that keeps exactly what you type ("0.", ".25", "28.5") and tidies
the display when you leave it.

RATES TO 2 DECIMAL PLACES - in the build-up editor (the rate box and the
price-list rate shown in it) and on the price list. The EXACT rate is still
used in every calculation, so prices do not change (Mech Fixed SP stays
32.04); hover over a rate (or click into it) to see the exact figure - e.g.
Discs 0.23 (exact 0.23296).

Checked in a REAL browser (Chromium), typing ONE KEY AT A TIME: own item rate
"0.25" -> 0.25, line 0.26 with its 5% waste; ".25" -> 0.25; Width "1.2";
waste "12.5" -> VCL line 0.93; rates shown 0.83 / 0.23 with the exact figure
on hover; on an estimate MCD "2.5" and Profit "28.5" stuck and moved the total
(21,334.00 -> 21,418.00); day rate 325.50. All 165 pages pass the browser
check. Built from your deployed packages (1022-1107, verified against their
zips); each file checked identical to the tested version before zipping.
