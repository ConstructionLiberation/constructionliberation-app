pkg885 - The guardrail. A missed route now breaks instead of leaking.
=====================================================================

ONE FILE.  lib/db.js  - not new.

THIS ONE IS DESIGNED TO BREAK THINGS. That is the point. Deploy it when you can
watch it, not last thing at night.


WHAT IT DOES
------------
With tenancy on, if a request reaches the database without a customer having
been resolved, getRedis() now THROWS instead of falling back to the global
client.

Before: an API route that was never wrapped in withTenant fell through and read
ROCK'S database. It worked. It looked completely normal. Served to a different
customer it would have produced plausible figures belonging to the wrong
company, and nothing anywhere would have said so.

After: that route is a broken page. Loud, immediate, one line to fix.

This is the single most valuable step in the whole exercise, because it converts
the one failure nobody can see into the one failure everybody can.

Proven:

    tenancy ON
      wrapped route, customer resolved     -> TENANT:rock
      UNWRAPPED route, no customer         -> THROWS

    tenancy OFF (the rollback)
      no customer, single tenant           -> GLOBAL       rollback still works

    tenancy ON, globals also removed
      wrapped route, customer resolved     -> TENANT:rock
      UNWRAPPED route, no customer         -> THROWS

It throws rather than falling back to the in-memory store, which was the other
option. An empty store looks like "no data"; a throw looks like "this code is
wrong", which is what it is.


WHAT I CHECKED CANNOT HIT IT
----------------------------
  health-check.js            unwrapped, touches no database
  tenant-setup.js            unwrapped, but names its own database since pkg884
  platform/tenants.js        unwrapped, uses the control database's own
                             credentials
  deliveries-notify.js       a module, called inside hs-expiry-email, so a
                             customer IS in scope
  forEachTenant heartbeats   both inside the loop; and heartbeat() swallows its
                             own errors, so it could not fail a job anyway
  every lib file             checked for database access at module scope - none

So nothing legitimate reaches the throw. Anything that does is a genuine miss.


THE ROLLBACK IS UNCHANGED
-------------------------
Delete TENANCY_ENABLED in Vercel and redeploy. The throw is gated on it, so
single-tenant behaviour returns exactly as before. Ninety seconds.
